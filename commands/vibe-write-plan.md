# vibe-write-plan

## Purpose

Write an implementation plan.

## When to use

Use after spec/design approval or when a clear task needs multi-step execution.

## Required inputs

Accepted spec or task; likely files; constraints; validation commands; risks.

## Step-by-step behavior

1. Confirm approval or authoritative requirement summary.
2. Inspect likely files and conventions.
3. List ordered tasks with file targets and dependencies.
4. Attach checks to behavior or structure changes.
5. Name risks, rollback points, and explicit non-scope.

## Outputs

Plan with scope, files, ordered steps, risks, rollback points, and verification commands.

## Verification or stopping conditions

Stop if the spec is unapproved, target files are unknown for risky work, or validation cannot be defined.
