# vibe-brainstorm

## Purpose

Brainstorm before coding.

## When to use

Use when intent, constraints, risks, or solution shape are not settled.

## Required inputs

User request; known constraints; relevant repo context; deadline or acceptance criteria if available.

## Step-by-step behavior

1. Restate the request and separate facts from assumptions.
2. Ask only high-value clarifying questions, or record explicit assumptions when safe.
3. Present practical options with trade-offs, risks, and validation paths.
4. Recommend the smallest safe next step.
5. For non-trivial work, move to spec/design approval before implementation.

## Outputs

Clarified intent, assumptions, options, recommendation, open questions, and next command/skill to use.

## Verification or stopping conditions

Stop before implementation if a missing answer would change scope, architecture, data handling, or acceptance criteria.
