# Quality Score Trend Dashboard Guide

## Overview

The Quality Score Trend Dashboard provides **time-series visualization data** for quality telemetry events collected across validation runs. It transforms raw NDJSON telemetry events into structured daily, weekly, and monthly trend data, making it easy to spot quality regressions, improvements, and patterns over time.

Generated by `scripts/quality-trend-dashboard.mjs`, the dashboard produces:

- **`dashboard.json`** — Structured JSON with daily/weekly/monthly time-series data, per-gate breakdowns, and sparkline-ready pass-rate history. Suitable for feeding into charting libraries (e.g., Chart.js, D3, Observable).
- **`dashboard.md`** — Human-readable markdown report with summary tables and recommendations.

Output location: `docs/reports/quality-trend/`

## How to generate

### Basic usage

```bash
npm run dashboard:trend
```

This reads telemetry events from the default NDJSON path (`docs/metrics/quality-telemetry-events.ndjson` or `docs/metrics/quality-events.ndjson`) and writes both JSON and markdown to `docs/reports/quality-trend/`.

### Options

```bash
# Specify a custom events file
node scripts/quality-trend-dashboard.mjs --events docs/metrics/my-events.ndjson

# Filter to the last 7 days
node scripts/quality-trend-dashboard.mjs --since 7d

# Filter to the last 30 days
node scripts/quality-trend-dashboard.mjs --since 30d

# Filter by a specific model
node scripts/quality-trend-dashboard.mjs --model claude-sonnet-4

# Output JSON to stdout (no file write)
node scripts/quality-trend-dashboard.mjs --json

# Specify an output directory
node scripts/quality-trend-dashboard.mjs --output-dir docs/reports/my-trend
```

### Combine filters

```bash
node scripts/quality-trend-dashboard.mjs --since 14d --model gpt-4o-mini --json
```

## How to read the dashboard

### Summary section

The summary gives you a quick health check:

| Metric | What it means |
|---|---|
| Total events | Number of telemetry events analyzed |
| Passes / Failures | Raw counts of passing and failing gate runs |
| Warnings | Gates that triggered warnings (not failures) |
| Skips | Gates that were skipped |
| Timeouts | Gates that timed out |
| Overall pass rate | Percentage of all events that passed |

**Rule of thumb:** A pass rate consistently above 90% indicates healthy quality. Below 80% warrants investigation.

### Daily, Weekly, Monthly trends

Each time-series table shows:

| Column | Meaning |
|---|---|
| Date / Week / Month | The time period |
| Runs | Total gate runs in that period |
| Passes | Passing gate runs |
| Failures | Failing gate runs |
| Pass rate | Percentage of passes |
| Avg duration | Average execution time per gate run |

**How to spot trends:**

- **Declining pass rate** over consecutive periods → regression or new issues
- **Improving pass rate** → fixes or better configuration taking effect
- **Sudden drop** → investigate recent changes (code, config, or model updates)
- **Duration spikes** → gate scripts may be slowing down (larger scope, more files)

### Per-Gate Breakdown

Shows each gate's lifetime statistics:

| Column | Meaning |
|---|---|
| Gate | Gate identifier (e.g., `traceability`, `secret-scan`) |
| Runs | Total number of times this gate was run |
| Pass rate | Lifetime pass percentage |
| Avg duration | Average execution time |
| Failures | Total failure count |
| Warnings | Total warning count |

**Use this to:** identify consistently problematic gates that may need logic updates or threshold adjustments.

### Worst-Performing Gates

Lists gates with the highest failure counts. Focus improvement efforts here.

### Recommendations

Auto-generated suggestions based on trend analysis:

- **Low pass rate gates** — suggests reviewing gate logic or configuration
- **Declining pass rate** — flags recent regression over the last 3 days
- **Improving pass rate** — positive signal worth noting

## The dashboard.json schema

```json
{
  "schemaVersion": "2.7.0",
  "generatedAt": "ISO date string",
  "source": "path to events file",
  "filters": {
    "since": "ISO date or null",
    "model": "model ID or null"
  },
  "summary": {
    "totalEvents": 0,
    "totalPasses": 0,
    "totalFailures": 0,
    "totalWarnings": 0,
    "totalSkips": 0,
    "totalTimeouts": 0,
    "overallPassRate": 0.0
  },
  "timeSeries": {
    "daily": [
      {
        "date": "2026-06-19",
        "totalRuns": 10,
        "totalPasses": 8,
        "totalFailures": 2,
        "passRate": 80.0,
        "avgDurationMs": 150,
        "gates": [
          { "gateId": "validate-repo", "runs": 5, "passes": 5, "failures": 0, "passRate": 100.0 }
        ],
        "models": [
          { "modelId": "unknown", "runs": 10, "passes": 8, "failures": 2, "passRate": 80.0 }
        ]
      }
    ],
    "weekly": [ /* same structure with "week" field */ ],
    "monthly": [ /* same structure with "month" field */ ]
  },
  "gates": [
    {
      "gateId": "validate-repo",
      "totalRuns": 50,
      "totalPasses": 48,
      "totalFailures": 2,
      "totalWarnings": 0,
      "passRate": 96.0,
      "avgDurationMs": 131,
      "dailyRates": [
        { "date": "2026-06-19", "passRate": 100.0, "runs": 5 }
      ]
    }
  ]
}
```

The `dailyRates` array inside each gate object is designed for **sparkline visualization** — each entry maps a date to that gate's pass rate, showing how a specific gate performs over time.

## Integration with other tools

### Charting with the JSON output

The `dashboard.json` is structured for easy consumption by visualization tools:

```javascript
// Example: Chart.js config for daily pass rate
const dailyData = dashboard.timeSeries.daily.map(d => ({
  x: d.date,
  y: d.passRate
}));
```

### CI/CD pipeline

```bash
# Generate trend dashboard in CI
npm run dashboard:trend

# Or with explicit events path
node scripts/quality-trend-dashboard.mjs --since 7d
```

### Combining with quality-telemetry

```bash
# Full pipeline: run quality engine → collect telemetry → generate dashboard
npm run validate:all
node scripts/quality-telemetry.mjs --engine docs/reports/quality-engine/<report>.json
npm run dashboard:trend
```

## Ghi chú tiếng Việt

Dashboard xu hướng chất lượng được tạo tự động từ dữ liệu telemetry. File `dashboard.json` chứa dữ liệu có cấu trúc phù hợp cho biểu đồ, còn `dashboard.md` là báo cáo dạng bảng. Dùng `npm run dashboard:trend` để tạo mới.

## Troubleshooting

| Problem | Solution |
|---|---|
| "No daily data available" | The events file may be empty or not found. Run `quality-telemetry.mjs` first to collect events. |
| "Events file not found" | Ensure `docs/metrics/quality-telemetry-events.ndjson` exists, or specify `--events <path>`. |
| Zero events with `--since` | The filter may be too restrictive. Try a longer duration or omit the filter. |
| No gate data | Events may have an unexpected format. Use `--json` to inspect raw data. |
