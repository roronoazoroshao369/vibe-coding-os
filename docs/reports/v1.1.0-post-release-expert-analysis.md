## 1. Tóm tắt điều hành

v1.1.0 đã chuyển Vibe Coding OS từ trạng thái v1.0 “trusted workflow framework” sang một bản hardening đáng kể hơn: runtime schema được căn chỉnh, validation pipeline mở rộng, adapter coverage tăng, CLI smoke rộng hơn, và docs release-facing đã phần lớn đúng trạng thái release.

- **Release v1.1.0 hợp lệ về chức năng:** toàn bộ validation/smoke suite hiện tại PASS.
- **Core markdown-first vẫn là điểm mạnh nhất:** skills/commands/templates + adapters tạo ra discipline layer portable cho Claude Code, Codex, Cursor, Gemini.
- **Rủi ro lớn nhất sau release không phải source code mà là status/docs drift:** Dashboard/README còn một số số liệu lặp lại bị stale.
- **Runtime đã tốt hơn v1.0 nhưng chưa phải production-grade multi-agent runtime:** hiện phù hợp làm local opt-in state companion; để support workflow đa-agent thật cần hợp đồng chặt hơn: task claim/lease, workflow graph, action/event trace, approval/safety, migration.

## 3. Reviewer Agent — audit repo trạng thái hiện tại

### 3.1 Điểm tốt

- Validation pipeline mạnh hơn v1.0: 16 gates gồm release metadata, bilingual sync, markdown links.
- CLI smoke đã mở rộng lên 20 commands, bao gồm init cho Claude Code, Codex, Cursor, Gemini.

- `docs/releases/v1.1.0.md` phản ánh đúng baseline release: 16 gates, 20 CLI tests, 6 adapter smoke, 3 runtime smoke.

### 3.2 Gaps phát hiện

#### High — Dashboard còn stale ở validation count

Evidence:

- `docs/DASHBOARD.md` vẫn có dòng `Overall: 13/13 gates passed`.
- Ground truth hiện tại: `validate:all` là `16/16 checks passed`.
- `docs/releases/v1.1.0.md` đã ghi đúng 16/16.

Impact: Dashboard là health surface quan trọng; nếu stale thì giảm trust của release.

Recommendation:

- Sửa generator/dashboard để emit 16/16.
- Mở rộng `check-dashboard-sync` để validate gate count từ `scripts/validate-all.mjs`.

#### High — Dashboard chưa thể hiện v1.1 trong Version Progress

Evidence:

- `docs/DASHBOARD.md` version progress chỉ liệt kê đến v1.0.
- `docs/ROADMAP-STATUS.md` đã có v1.1 complete.

Recommendation:

- Dashboard generator cần include latest package version/release line.
- Release metadata gate nên fail nếu current version không xuất hiện trong dashboard progress.

#### High — README/README.vi có orphan count sai

Evidence:

- README banner nói `0 orphans`.
- Dashboard data cho thấy `Orphan templates | 11`.

Interpretation: Có thể “0 orphans” đang ám chỉ orphan commands/skills, nhưng wording hiện tại gây hiểu nhầm.

Recommendation:

- Đổi thành: `0 orphan commands/skills, 11 orphan templates (warnings)` hoặc `11 template warnings`.
- Release metadata validator nên so sánh orphan counts với dashboard data.

#### Medium-High — README body còn stale `41 templates`

Evidence:

- Top banner đã nói 54 templates.
- Nhưng README body còn chỗ nói `41 templates`.
- README.vi cũng có chỗ tương tự.

Recommendation:

- Replace các số lặp trong README/README.vi từ 41 → 54.
- Validator nên scan repeated inventory claims, không chỉ headline.

#### Medium-High — Vietnamese roadmap/status doc stale

Evidence:

- `docs/vi/strategy-and-roadmap.md` vẫn nói repo ở v0.4.0/13 gates/41 templates/v1.0 RC-ready.

Recommendation:

- Hoặc update lên v1.1.0, hoặc đổi tên/ghi rõ “historical”.
- Bilingual sync validator nên include current-facing docs trong `docs/vi/**`.

#### Medium — Runtime smoke chưa exercise đủ runtime command paths

Hiện smoke chủ yếu validate state và một workflow run. Chưa cover sâu:

- `runtime:task`
- `runtime:memory`
- `runtime:checkpoint`
- `runtime:team`
- `runtime:session`
- `runtime:daemon`
- `runtime:mcp`
- `runtime:team-run`
- `runtime:install`

Recommendation:

- v1.2 nên có `smoke-test:runtime-cli` hoặc mở rộng `smoke-test:runtime` để chạy create/list/update flow cho từng runtime CLI.

#### Medium — Schema vẫn permissive

Nhiều schema dùng `additionalProperties: true`. Điều này tốt cho forward compatibility nhưng yếu để bắt drift.

Recommendation:

- v1.2 dùng `metadata`/`extensions` làm escape hatch, còn top-level stable fields nên `additionalProperties: false`.

#### Medium — Local JSON schema validator chưa full JSON Schema

Validator local là zero-dep subset, chưa enforce đầy đủ các keyword như `additionalProperties`, `maxLength`, `minItems`, `pattern`, `uniqueItems`.

Recommendation:

- Hoặc document rõ subset, hoặc thêm optional AJV job cho CI/release.

#### Medium — CI chưa có runtime smoke là named gate

`validate:all` pass 16/16 nhưng runtime smoke đang được chạy riêng. Release notes nói runtime smoke baseline, nhưng CI full gate không hiển thị runtime smoke là một gate riêng.

Recommendation:

- Thêm `smoke-test:runtime` vào `validate:all` hoặc thêm CI job rõ ràng.
- Cân nhắc matrix Node 20/22.

## 4. Researcher Agent — so sánh với CrewAI / LangGraph / OpenHands / Cursor-Codex ecosystem

### 4.1 Định vị hiện tại

Vibe Coding OS không nên định vị là “agent runtime cạnh tranh trực tiếp CrewAI/LangGraph/OpenHands”. Điểm mạnh hơn là:

> **Portable discipline layer cho AI coding agents:** spec-first workflow, skills, commands, templates, safe memory, reference attribution, validation gates — dùng được với Claude Code, Codex, Cursor, Gemini và các agent khác.

### 4.2 So với CrewAI

CrewAI mạnh ở executable multi-agent orchestration: agents, roles, tasks, processes, tool execution.

Vibe mạnh hơn ở:

- Markdown portability.
- Cross-tool adoption.
- Engineering process discipline.
- Validation/reference/memory safety.

Gap của Vibe:

- Chưa có declarative crew/team execution model đủ chặt.
- Chưa có tool registry/capability routing mạnh.
- Team orchestration vẫn guidance-first nhiều hơn executable contract.

### 4.3 So với LangGraph

LangGraph mạnh ở graph/state/checkpoint/human-in-loop/resumability/observability.

Vibe mạnh hơn ở:

- Low ceremony.
- Repo-native docs.
- Works without building a graph app.
- Human-readable engineering artifacts.

Gap của Vibe:

- Chưa có workflow graph DSL.
- Chưa có durable resumable state-machine engine.
- Chưa có interrupt/resume semantics rõ.
- Observability còn nhẹ.

### 4.4 So với OpenHands

OpenHands mạnh ở full autonomous coding runtime: shell/browser/editor/sandbox/agent loop.

Vibe mạnh hơn ở:

- Không buộc người dùng đổi runtime.
- Dùng được như process/quality layer trên tool sẵn có.
- Safety/provenance/memory discipline.

Gap của Vibe:

- Không có sandbox/editor/browser integrated runtime.
- Không có autonomous planner/actor loop hoàn chỉnh.
- Chưa có benchmark harness kiểu SWE-bench.

### 4.5 So với Cursor/Codex/Claude Code ecosystem

Native tools mạnh ở UX và execution loop. Vibe nên làm lớp chuẩn hóa hành vi và chất lượng.

Gap:

- Setup vẫn còn copy/symlink/paste heavy ở một số adapter.
- Chưa có polished interactive installer/package distribution.
- Chưa có skill-pack installer/updater thật mượt.

### 4.6 Differentiators nên double down

1. Markdown-first, runtime-optional.
2. Engineering discipline over autonomy.
3. Cross-tool adapter surface.
4. Reference intelligence + attribution.
5. Safety and memory privacy.
6. Bilingual EN/VI onboarding.
7. “Covered by tooling” vs “covered by advice” transparency.

## 5. Architect Agent — đánh giá runtime layer

### 5.1 Maturity rating

- Markdown/core framework: **cao**
- Runtime helper: **trung bình**
- Multi-agent orchestration: **early/experimental**
- Schema/contract rigor: **medium-low**
- Safety/traceability readiness: **medium**
- Production-like workflow runtime: **chưa sẵn sàng**

Runtime hiện phù hợp cho:

- Human-supervised local task state.
- Simple dependency-based sequencing.
- Memory ingest/search.
- Checkpoint notes.
- Session summaries.
- Team spec/tmux experiments.
- MCP state access nhỏ và có kiểm soát.

Runtime chưa phù hợp cho:

- Autonomous multi-agent task claiming.
- Concurrent agents edit overlapping files an toàn.
- Enforced review/verification gates.
- Full provenance intent → task → action → checkpoint → merge.
- Policy-based safety enforcement.
- Reliable resumability after failure.

### 5.2 Contract weaknesses

1. Schemas quá permissive.
2. `CURRENT_SCHEMA_VERSION = 1` quá coarse.
3. Store writes chưa validate full record trước persistence.
4. Local schema validator chưa enforce đủ keywords.
5. Task model thiếu claim/lease/priority/acceptance criteria/evidence refs/risk/history.
6. Team model chưa có role ID, permissions, input/output contract, conflict policy, merge policy.
7. Session/workflow-run state còn shallow.
8. Action/event trace chưa nối chặt tới task/session/workflow/checkpoint.
9. Safety contract chưa được enforce trong runtime actions/MCP/tmux/daemon.
10. MCP input schemas còn ad hoc, chưa share canonical schema.
11. Locking/concurrency chỉ đủ local light use.
12. Memory retrieval governance còn thiếu expires/allowed contexts/provenance/privacy review.

### 5.3 v1.2 contract changes đề xuất

P0/P1 nên tập trung vào:

- Runtime envelope v2: `schemaVersion`, `contractVersion`, `runtimeId`, `revision`, `metadata`, `extensions`.
- Common item envelope: `createdBy`, structured `source`, `trace`, timestamps.
- `additionalProperties: false` top-level + `metadata/extensions` escape hatch.
- Validator support thêm: `additionalProperties`, `maxLength`, `minItems`, `pattern`, `uniqueItems`.
- Task v2: `status` mở rộng, `phase`, `priority`, `claim`, `acceptanceCriteria`, `allowedPaths`, `verification`, `handoff`, `history`.
- Team v2: `orchestration`, roles có `id`, capabilities, allowed/denied paths, input/output contracts, safety policy, review gates.
- Workflow-run v2: refs, gates, artifacts, resume state.
- Runtime-action v2 + runtime-event schema.
- Checkpoint v2 evidence model.
- Runtime approval schema + safety integration.
- Runtime tool contract schema để sync CLI/MCP/store.
- Migration manifest cho v1 → v2.
