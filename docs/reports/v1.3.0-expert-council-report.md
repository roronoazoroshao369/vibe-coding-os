# Vibe Coding OS — Expert Council Report: Post-v1.3.0

**Date:** 2026-06-17
**Session:** Post-release v1.3.0 council meeting
**Attendees:** Reviewer Agent, Researcher Agent, Architect Agent
**Facilitator:** Hermes Agent (orchestrator)

---

## Executive Summary

v1.3.0 successfully moved the runtime from "contract-rich but mostly passive" to "enforced, observable, and recoverable enough for local multi-agent experiments." However, all three agents agree that the **highest-impact next work is NOT more runtime features** — it is fixing gaps in the current release and making the framework adoptable by real developers.

### Consensus Recommendations (ordered by urgency)

1. **Fix critical doc corruption** in `docs/ROADMAP-STATUS.md` — release quality blocker
2. **Fix schema enforcement wiring** — JSON schemas exist but are not actually validated at runtime
3. **Adopt "Portable Workflow Contract" positioning** — don't compete with CrewAI/LangGraph/OpenHands as runtime
4. **Prioritize P2 Adoption UX** — `vibe export`, `vibe doctor`, `FIRST-WORKFLOW`, skill packs
5. **Add runtime config layer** — current config is template-only, not functional
6. **Build formal task state machine** — current status enum allows illegal transitions
7. **Harden event sourcing** — events are side-effects, not source of truth

## 1. Reviewer Agent — Risk & Quality Audit

### Critical Findings

| # | Finding | Severity | Files |
|---|---------|----------|-------|
| 1 | `docs/ROADMAP-STATUS.md` corrupted — garbage text on line 124+ | **Critical** | `docs/ROADMAP-STATUS.md:120-124` |
| 2 | Schema validation not wired — `Enforcement.assertValidItem()` is a no-op without validator; all stores instantiate `new Enforcement()` without attaching one | **Critical** | `runtime/core/enforcement.mjs:25-31`, all store files |
| 3 | Event log + store writes not transactional — store write succeeds but event append can fail, creating silent divergence | **Critical** | `runtime/core/events.mjs:11-24`, all store write patterns |
| 4 | Approval gate has duplicate-approval race — `withApprovalGate()` finds + creates approval outside lock | **High** | `runtime/core/approval-gate.mjs:216-255` |
| 5 | Dashboard template count mismatch (56 vs 54) | **Low** | `docs/DASHBOARD.md:13,82` |

### Most Dangerous Gap

> "Store writes and event appends are not transactional. `appendEvent()` is not locked or schema-validated. `listEvents()` silently skips malformed lines by default. Recovery/replay uses non-strict parsing. This can cause silent divergence between actual JSON store state and replay/audit state."

### Recommended Priority

1. Wire real JSON Schema validation into all stores
2. Add event schema validation and optional strict mode for replay
3. Make event cleanup atomic
4. Add concurrent claim tests and stale lock handling
5. Fix ROADMAP-STATUS.md corruption

## 2. Researcher Agent — Ecosystem Comparison & Positioning

### Executive Finding

> "Vibe Coding OS is not best positioned as a runtime competitor to CrewAI, LangGraph, OpenHands, Cursor, Codex, or Gemini. Its strongest positioning is: **The portable discipline, safety, memory, spec, and validation layer for AI-assisted coding across tools.**"

### Killer Feature Proposal: "Agent Workflow Portability Kit"

```bash
vibe init --profile react-nextjs --tools cursor,codex,claude,gemini
vibe doctor --project
vibe export all
```

This produces a complete, validated, portable AI workflow layer:
- `AGENTS.md`
- `CLAUDE.md`
- `GEMINI.md`
- `.cursor/rules/*.mdc`
- selected skill pack
- spec/plan/task templates
- validation gates
- memory/privacy policy
- optional runtime config

**No competitor provides this cross-agent portability with validation and safety.**

### CrewAI Gap Analysis

| What CrewAI Has | What Vibe Lacks | Impact |
|----------------|-----------------|--------|
| `agents.yaml` + `tasks.yaml` scaffold | No runnable project scaffold | High |
| First-class agent/task DSL | No concise workflow spec | High |
| Production Flows orchestration | No workflow engine | Medium |
| Enterprise observability | No live UI/control plane | Medium |
| Official plugin/skill installers | Manual copy/paste export | Very High |

### LangGraph Gap Analysis

| What LangGraph Has | What Vibe Lacks | Impact |
|-------------------|-----------------|--------|
| Explicit state graph | No state machine | High |
| Durable execution + resume | Events are side-effects | High |
| Checkpoint diff + replay | Incomplete event payloads | Medium |
| Human interrupt semantics | Only approval gates | Low |

### OpenHands Gap Analysis

| What OpenHands Has | What Vibe Lacks | Impact |
|-------------------|-----------------|--------|
| Real sandbox (Docker/VM) | Policy-level safety only | High (trust) |
| Agent control center UI | No observability UI | Medium |
| Multi-backend agent management | Local file only | Low |
| Webhook/scheduled automations | No automation triggers | Low |

### Adoption Barriers (ranked)

1. **Too much inventory** — 90 skills / 68 commands / 56 templates is intimidating → need "5-minute path"
2. **Manual installation** → need `vibe export cursor|codex|gemini|claude`
3. **Unclear runtime value** → need use-case docs
4. **No live UI** → need `vibe trust-report --html`
5. **Safety misunderstood** → need security model doc
6. **No integration docs** → need CrewAI/LangGraph/OpenHands comparison
7. **Docs drift** → need validation gate for count consistency

|-----------|--------|-------|
| Enforcement | 6.5/10 | Good skeleton, incomplete wiring |
| Concurrency | 5.5/10 | Local-file best-effort, no stale lock recovery |
| Recovery | 6/10 | Events incomplete, replay falls back to stores |
| Observability | 5.5/10 | Basic audit, not production observability |
| Extensibility | 6/10 | Modular but not a stable extension platform |
| Documentation | 6/10 | Good implementation docs, missing operator/architecture docs |
| **Overall** | **6/10** | Strong for optional runtime, not enough for real team trust |

### What Is Still Demo-Grade

- **Event sourcing**: Events are notifications after state mutation, not the source of truth
- **Task lifecycle**: Any allowed status can be assigned directly, no transition validation
- **Concurrency**: Local-file best-effort, no compare-and-swap or revision checks
- **Adapter safety**: Allowlist-only, not full contract
- **Configuration**: Template-only, not a loaded/configurable runtime layer
- **Observability**: Audit-lite, no correlation/causation IDs, no metrics

## 4. Cross-Cutting Consensus

### All 3 agents agree:

1. **Positioning**: "Portable workflow contract across agents" — not a runtime competitor
2. **P2 first**: Adoption UX before deeper runtime architecture
3. **Security doc needed**: Policy-level safety must be explicitly documented
4. **Schema enforcement**: Critical gap — schemas exist but aren't enforced at write time
5. **Event store consistency**: Most dangerous data integrity risk

### Points of disagreement:

| Topic | Reviewer | Researcher | Architect |
|-------|----------|------------|-----------|
| v1.3.0 readiness | "Has critical doc corruption" | "Strong but needs adoption layer" | "6/10, usable for experiments" |
| Event sourcing priority | P1 (data loss risk) | P2 (adoption matters more) | P2 (config + state machine first) |
| UI/control plane | Not mentioned | P2/P3 (nice to have) | v1.5 (defer) |

## 5. Proposed v1.4 Roadmap (Synthesized)

### Theme: "Portable Adoption + Runtime Kernel Foundation"

### Sprint Structure

#### Sprint 1 — Critical Fixes + Docs (8h)
- Fix ROADMAP-STATUS.md corruption
- Fix dashboard template count mismatch
- Fix README v1.3.0 "What's new" section
- Add ROADMAP-STATUS validation gate
- Fix approval gate race condition
- Create security model doc (`docs/SECURITY-MODEL.md`)

#### Sprint 2 — Adoption UX Core (20h)
- `docs/FIRST-WORKFLOW.md` + `docs/vi/FIRST-WORKFLOW.md`
- `vibe doctor --project`
- `vibe export cursor|claude|codex|gemini`
- `--help/--version` across runtime scripts
- Real-world React/Next.js example

#### Sprint 3 — Skill Packs + Discovery (16h)
- `vibe install-pack core-solo`
- `vibe install-pack memory-safe`
- `vibe install-pack multi-agent`
- `vibe install-pack react-nextjs`
- Skill catalog with search
- `CONTRIBUTING-SKILLS.md`

#### Sprint 4 — Schema Enforcement Hardening (16h)
- Wire JSON Schema validation into `Enforcement` constructor
- Pass `collectionSchema` to all `writeJsonAtomic()` calls
- Add read-time validation for recovery/migration/audit
- Add event schema validation
- Add concurrent claim tests

#### Sprint 5 — Task State Machine (24h)
- `runtime/tasks/state-machine.mjs`
- Transition table with guards
- Review/verification flow

#### Sprint 6 — Event Store v2 (32h)

- Correlation/causation IDs
- Full-fidelity event payloads
- Deterministic replay without store fallback
- Snapshot integrity + checksums
- Config layer foundation

#### Sprint 7 — Multi-Workflow + Adapter Protocol (36h)
- Workflow definitions + runs
- Basic scheduler
- Adapter manifest schema
- Standard action envelope
- Config-loaded tool contracts

#### Sprint 8 — Integration Docs + Ecosystem (12h)
- CrewAI comparison + integration doc
- LangGraph comparison + integration doc
- OpenHands comparison + integration doc
- Trust report (`vibe trust-report`)
- Local HTML dashboard (`vibe dashboard --html`)

### v1.4 target maturity: 7.5-8/10
