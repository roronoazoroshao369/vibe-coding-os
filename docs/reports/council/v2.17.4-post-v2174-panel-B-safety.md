## Injection Defense Depth

### What the Scanner Catches

The injection scanner at `scripts/validate-injection.mjs` (220 lines) scans 596 files + 1 MCP manifest. Patterns from `runtime/core/injection-patterns.mjs` cover:

**Blocking (error — exits 1):**
- **instruction-override** — "ignore all previous instructions" variants
- **role-reassignment** — "you are now a..."
- **system-prompt-override** — "new system prompt:"
- **safety-bypass** — "disable safety guardrails"
- **exfiltration-directive** — verb + secret + destination (triple-gated to reduce FPs)
- **bidi-override-unicode** — U+202A..U+202E, U+2066..U+2069 invisible reorder chars
- **mcp-shell-exec** (mcp scope only) — dangerous shell launch commands in `.mcp.json`

**Warning (non-blocking):**
- **conceal-from-user** — "don't tell the user"
- **zero-width-unicode** — U+200B..U+2060 invisible chars
- **base64-blob** — 200+ char base64 strings

### What It Misses

1. **Regex-blind payloads** — Any novel injection that doesn't match known regex shapes passes silently. The scanner explicitly acknowledges this ("best-effort only").
2. **Encoding/split attacks** — Base64 split across multiple lines, hex-encoded commands, or concatenated string fragments evade single-line regex.
3. **Cross-file poisoning** — A benign artifact that references a second poisoned artifact is invisible at single-file scan time.
4. **MCP manifest command scope only** — Only `.mcp.json` command/args strings are scanned (not all JSON manifests). Any other manifest format is invisible.
5. **No runtime injection detection** — The scanner is pre-commit static analysis only. There is no runtime monitoring of what payloads arrive via MCP calls or tool invocation.
6. **Allowlist blind spots** — 11 files are allowlisted entirely, including `guard-bypass-protocol/SKILL.md` and council audit reports that quote payloads. The allowlist is well-documented but each entry is a deliberate blind spot.
7. **No MCP argument injection protection** — The MCP server passes user-supplied arguments directly to handler functions without input sanitization or injection scanning of arguments.

## MCP Server Security

File: `runtime/mcp/server.mjs` (211 lines) + `scripts/runtime-mcp.mjs` (entrypoint)

| Dimension | Status | Details |
|---|---|---|
| **Authentication** | ❌ None | The MCP server connects over `StdioServerTransport` with zero auth. Any local process can call it. No API key, no session token, no TLS. |
| **Sandboxing** | ❌ None | Runs as the same OS user with full filesystem access. No chroot, no container, no capabilities drop. Security-model.md explicitly disclaims sandboxing. |
| **Input Validation** | 🟡 Partial | JSON Schema `additionalProperties: false` on all tool input schemas prevents field injection. But values are passed raw to handler functions (e.g., `searchMemory(store, args.query)` with string that could include query injection). |
| **Tool Allowlist** | ✅ Present | `assertToolAllowed(tool.name, 'mcp', defaultContracts)` at line 197 gates every call. The MCP contract allows 16 tools: 6 core (task.*, memory.*, checkpoint.create) + 5 vibe command tools + 4 autopilot tools + 1 from buildTools (t=6). |
| **Approval Gate** | ✅ Present | `withApprovalGate` wraps write handlers. Tools with `risk.level: 'review'` (task.update, memory.ingest, checkpoint.create, autopilot.start, autopilot.stop) are gated. |
| **Rate Limiting** | ❌ None | No budget, no rate limits, no per-call token accounting. The MCP server is fully open after auth bypass. |
| **Audit Logging** | ✅ Present | `audit.log` for autopilot operations; approval events logged. |

**Key Concern:** The MCP server has no authentication and no sandbox. Because it uses `StdioServerTransport`, it's accessible to any local process or MCP client that connects. While this is "opt-in" (`@modelcontextprotocol/sdk` not installed by default), once enabled it provides no defense against a local attacker or a compromised agent that has acquired file write access (e.g., to modify `.mcp.json`).

### Tool Contract Analysis

`runtime/core/tool-contract.mjs` defines allowed tool sets per adapter:

- **native**: empty (no tools allowed)
- **mcp**: 16 tools (task.*, memory.*, checkpoint.create, vibe.*, autopilot.*)
- **tmux**: empty
- **daemon**: empty
- **hermes**: same 16 tools as mcp
- **ai-assistant**: same 16 tools

The contract is static — defined at import time, never updated dynamically. `assertToolAllowed()` is called in the MCP server handler at line 197 but the `defaultContracts` map is not extensible at runtime. Any new adapter not in the map gets empty `[]` (fail-closed ✅).

## Key Findings

### 🔴 HIGH: MCP Server Has No Authentication or Sandboxing

`runtime/mcp/server.mjs` attaches `StdioServerTransport` with zero authentication. Any local process or modified `.mcp.json` gains full access to all 16 MCP tools including `task.update`, `memory.ingest`, and `autopilot.start` (which can define arbitrary policy rules). Once the SDK is installed (`npm install @modelcontextprotocol/sdk`), this is an open local RPC endpoint with no caller identity verification. The security model explicitly disclaims sandboxing, but there is **no compensating auth layer** at all.

### 🔴 HIGH: Injection Scanner Has No Mitigation for Novel Payloads

The scanner is pure static regex matching against known patterns. It has zero detection for:
- Encoding-based obfuscation (hex, Unicode normalization, multi-line splits)
- Semantic injection (instructions that are safe individually but dangerous combined)
- Payloads delivered through runtime arguments (not file content)
- The scanner's own header says "Best-effort only" — but there is **no runtime injection detection** anywhere in the codebase.

### 🟡 MEDIUM: `validate:no-deprecated-commands` CI Gate Has 2 Unscoped Gaps

The CI gate at `scripts/validate-no-deprecated-commands.mjs` passes cleanly, but **fails to scan** `.claude-plugin/plugin.json` (which contains 2 references to `vibe-parallel-explore` and `vibe-specify`) and the entire `skills/` directory (which contains 1 reference in `clarify-before-code/SKILL.md:77`). These are not false positives — they're real stale references that the gate should catch.

### 🟡 MEDIUM: 12/38 Validation Gates Are Failing

The meta-gate at `validate-all.mjs` reports only **26/38 checks passing**. Key failures: dashboard sync (6 mismatches), bilingual README version drift (English v2.17.4, Vietnamese v2.17.0), 4 broken markdown links, runtime behavioral tests, and CLI smoke tests. While most failures are metadata/sync issues (not security), they degrade confidence that the CI pipeline reliably blocks regressions.

### 🟡 MEDIUM: Approval Gate Bypass via `autopilot.start` with `autoApprove: true`

The `autopilot.start` MCP tool accepts an `autoApprove` parameter. When set to `true`, policy actions marked as requiring approval are auto-approved. Combined with arbitrary policy rules (including `file.write`, `shell.command` action patterns), this creates a mechanism to bypass the approval gate for any subsequent action within the autopilot session. The approval gate still creates records but the "auto-approve" path skips the human-in-the-loop check.

## Recommendations

### 1. Add MCP Server Authentication Layer (HIGH)

**Priority: Before next release.** Add at minimum a local token authentication to `runtime/mcp/server.mjs`:
- Generate a random MCP auth token on server start, output it to stderr
- Require the token in every MCP `CallToolRequestSchema` handler before executing
- Document in `docs/workflows/runtime-mcp-server.md` that `.mcp.json` must include the token
- This is a lightweight fix (no SDK dependency) that prevents trivial local-process attacks

The MCP server file path is `runtime/mcp/server.mjs` — modify the `startServer()` function and `CallToolRequestSchema` handler (lines 188–206).

### 2. Close `validate:no-deprecated-commands` Scanner Scope Gaps (MEDIUM)

**Priority: Before next release.** Edit `scripts/validate-no-deprecated-commands.mjs`:
- Add `.claude-plugin/plugin.json` to the targets list (or add `'.claude-plugin/'` to the walk targets)
- Add `skills/` to the targets list to catch stale command references in SKILL.md files
- Fix the 2 stale references in `.claude-plugin/plugin.json` after enabling the gate
- Consider adding `adapters/` for completeness

### 3. Add Runtime Argument Injection Scanning to MCP Handler (MEDIUM)

**Priority: v2.18.0.** Modify `runtime/mcp/server.mjs` to scan user-supplied tool arguments for injection patterns before passing them to handler functions:
- Import `INJECTION_PATTERNS` from `runtime/core/injection-patterns.mjs`
- Scan `request.params.arguments` string values in the `CallToolRequestSchema` handler (line 188)
- Return `isError: true` if any blocking pattern is detected in arguments
- This closes the gap between static file scanning and runtime payload delivery
