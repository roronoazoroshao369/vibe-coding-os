F1. Defense-in-Depth (ADR-0003) Solved
3-layer chống prompt injection + RAG poisoning

Vấn đề giải quyết: Khi paste một prompt lạ từ StackOverflow / GitHub / blog vào Claude Code, attacker có thể ẩn instruction trong payload để bypass agent, exfiltrate secrets, hoặc pivot sang mục tiêu khác.

Cách hoạt động (3 layers): 

Layer 1 DETECT  →  injection-counters.mjs  (30 regex patterns)
                     + unicode normalization
                     + base64 decoder
                     + Shannon entropy check
                     + homoglyph detection

Layer 2 CONTAIN →  redactor.mjs  (30 secret patterns × 3 modes)
                     • postTool      — redact secrets in tool output
                     • postSession   — redact across full session
                     • postPublish   — redact before any external write

Layer 3 RECOVER →  tests/security/regression.mjs
                     + tests/security/baseline.json (100%/0% FP)
                     + CI-gated fail-build on regression
✅ Đau giải quyết: "Tôi paste prompt lạ vào agent và bị pwn" — Pattern phủ 18 OWASP LLM failure modes (9 ✅ / 7 🟡 / 0 ❌), trong đó direct injection, indirect injection, Bidi/RTL override, secret leakage, encoding bypass (base64, unicode, homoglyph) đều caught với 100% recall và 0% false positive trên canary corpus 49 payload.

F2. Trust Scoring (ADR-0004) NEW v2.16.0
Source-class gating + bypass-loop detection

Vấn đề giải quyết: Một attacker có thể iterate: lần 1 thử payload A, fail, lần 2 thử payload B (cùng intent), fail, lần 3 thử payload C — bypass. Hoặc giả mạo trusted source bằng cách lồng content từ README.md vào ~/.claude/skills/.

Cách hoạt động:

  • scoreSource(content, source): return {trust_class, risk_score, reasons, matches}
  • 3 trust classes: trusted (allow execution) / read-only (no tool) / isolated (sandbox)
  • detectBypassLoop(history): 3 attempts in 10 min = raise risk score
  • classifyLicense(license): 5 license classes (MIT/BSD → trusted, GPL → review, custom → isolated)
✅ Đau giải quyết: "Attacker iterate để tìm payload bypass" + "Giả mạo trusted source qua content lồng nhau". Đây là meta-defense mà hầu hết framework thiếu — không chỉ catch payload mà catch attacker behavior pattern.

F11. Hooks Pack (Claude Code) Solved
6 hook points, default-deny, exit-code semantics

Vấn đề giải quyết: Claude Code mặc định cho phép mọi tool call. Developer muốn safety net trước/sau tool execution nhưng không biết cách wire up.

6 hook points (từ claude-code-hooks-pack/SKILL.md, 72 lines):

  • PreToolUse — chạy TRƯỚC tool call, exit 2 = block (default-deny + allowlist)
  • PostToolUse — chạy SAU tool call (secret scan, output validate)
  • UserPromptSubmit — scan user prompt trước khi gửi Claude (injection detection)
  • Stop — khi session dừng, snapshot state
  • SessionStart — load context, set policy
  • SessionEnd — audit flush, write security event log

Exit-code semantics: 0 = allow, 2 = block (stderr → user), other = error.

✅ Đau giải quyết: "No safety net for tool calls" + "Agent exfiltrate qua Bash". Default-deny + ALLOWLIST_FILES = auditable narrow opt-outs thay vì global bypass. Inline markers cho phép suppress specific patterns khi cần.

F12. Guard Bypass Protocol NEW v2.10.0+
Opt-in offensive payload loader với audit trail

Vấn đề giải quyết: Red team cần test hệ thống với payload tấn công thật. Nhưng nếu để payload tự động load = poisoned AGENTS.md hoặc skill có thể trigger bypass. Cần gated loader với audit trail.

Mechanism (scripts/load-bypass-techniques.mjs):

  • Cần env var VIBE_ENABLE_OFFENSIVE_TECHNIQUES=1
  • Cần --authorization-ref matching regex ^[a-zA-Z0-9_-]{6,64}$
  • Mỗi load attempt ghi vào docs/security/bypass-load-attempts.log
  • Không load nếu thiếu 1 trong 2 điều kiện
✅ Đau giải quyết: "Poisoned skill tự động load bypass catalog" + "Red team không có cách test hợp pháp". Defense = cả 2 điều kiện (env + auth-ref) + audit log. vibe-bypass là tính năng CÓ SẴN, cần bảo vệ.

❌5 Unsolved Pain Points (Critical)

Hội đồng 3 panels đồng thuận đây là những gì còn thiếu. Mỗi gap có impact và recommended fix.

1. No RAG-ingest sanitizer (LLM01 indirect injection via vector store)
runtime/memory/vector-store.mjs và lessons-learned-db ingest documents mà KHÔNG gọi detectInjection(). Một poisoned upstream skill, reference clone, hoặc lesson có thể plant indirect-injection vector bypass validate-injection.mjs (chỉ scan files at rest, không scan text at retrieval time). Đây là attack surface LỚN NHẤT trong thực tế.

Fix: scripts/validate-rag-ingest.mjs gọi detectInjection() on every document entering vector store + lessons. Refuse ingest on severity=error.
2. Trust scorer test chỉ check shape (security-critical gap)
tests/security/trust-scorer.test.mjs gọi scoreSource(content, source) và assert return object có { trust_class, risk_score } thôi. Một scorer broken trả { trust_class: 'trusted', risk_score: 0 } cho MỌI input sẽ PASS test này. Đây là security-critical code với zero behavioral verification.

Fix: Add tests với known-malicious patterns (Bidi chars, encoded payloads, social-engineering) phải receive lower trust score. Test detectBypassLoop catches circular trust escalation.
3. Framework tự bản thân nó 4.5% test coverage (credibility gap)
374 artifacts (152 skills + 121 commands + 128 templates), chỉ 17 có direct test. v2.16.0 master plan tự thú: "Engineering B+ (8.0/10) — Governance mature, behavior under-verified (4.6% test coverage)." Hỏi users tin quality discipline trong khi framework untested = credibility gap.

Fix: v2.17.0 target ≥40% test coverage. Make npm run validate:all part of user-facing quickstart.
4. No redactor behavioral tests cho 3 modes (security-critical gap)
validate-redact.mjs test pattern coverage, nhưng KHÔNG test 3 modes (block / redact / log) produce different outputs cho cùng input. Mode-dependent logic hoàn toàn untested at behavioral level.

Fix: Verify block throws / redact returns masked / log writes to side channel. postTool mode phải NOT mutate original input.
5. No supply-chain SCA gate (LLM03 + A06 blind spot)
validate-licenses.mjs cover license headers, validate-provenance.mjs cover attribution, NHƯNG không có CVE/vulnerability scanning. package-lock.json committed nhưng pinned-hash integrity không asserted bởi validator. Malicious transitive dep = A06 (vulnerable components) + LLM03 (training data poisoning via dep) blind spot.

Fix: Add npm audit --omit=dev hoặc osv-scanner --lockfile=package-lock.json vào validate:all. Fail build on severity=high.
