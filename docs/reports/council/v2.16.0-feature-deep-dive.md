### F1. Defense-in-Depth (ADR-0003) — ✅ Solved

**3-layer chống prompt injection + RAG poisoning**

#### Vấn đề giải quyết
Khi paste một prompt lạ từ StackOverflow / GitHub / blog vào Claude Code, attacker có thể ẩn instruction trong payload để bypass agent, exfiltrate secrets, hoặc pivot sang mục tiêu khác.

#### Cách hoạt động (3 layers)

```
Layer 1 DETECT  →  injection-counters.mjs  (30 regex patterns)
                    + unicode normalization
                    + base64 decoder
                    + Shannon entropy check
                    + homoglyph detection

Layer 2 CONTAIN →  redactor.mjs  (30 secret patterns × 3 modes)
                    • postTool      — redact secrets in tool output
                    • postSession   — redact across full session
                    • postPublish   — redact before any external write

Layer 3 RECOVER →  tests/security/regression.mjs
                    + tests/security/baseline.json (100%/0% FP)
                    + CI-gated fail-build on regression
```

#### ✅ Đau giải quyết
"Tôi paste prompt lạ vào agent và bị pwn" — Pattern phủ 18 OWASP LLM failure modes (9 ✅ / 7 🟡 / 0 ❌), trong đó direct injection, indirect injection, Bidi/RTL override, secret leakage, encoding bypass (base64, unicode, homoglyph) đều caught với 100% recall và 0% false positive trên canary corpus 49 payload.

### F2. Trust Scoring (ADR-0004) — ✅ NEW v2.16.0

**Source-class gating + bypass-loop detection**

#### Vấn đề giải quyết
Một attacker có thể iterate: lần 1 thử payload A, fail, lần 2 thử payload B (cùng intent), fail, lần 3 thử payload C — bypass. Hoặc giả mạo trusted source bằng cách lồng content từ `README.md` vào `~/.claude/skills/`.

#### Cách hoạt động

- **`scoreSource(content, source):`** return `{trust_class, risk_score, reasons, matches}`
- **3 trust classes:**
  - `trusted` (allow execution)
  - `read-only` (no tool)
  - `isolated` (sandbox)
- **`detectBypassLoop(history):`** 3 attempts in 10 min = raise risk score
- **`classifyLicense(license):`** 5 license classes (MIT/BSD → trusted, GPL → review, custom → isolated)

#### ✅ Đau giải quyết
"Attacker iterate để tìm payload bypass" + "Giả mạo trusted source qua content lồng nhau". Đây là meta-defense mà hầu hết framework thiếu — không chỉ catch payload mà catch *attacker behavior pattern*.

#### Files thật trong repo
- `security/defense/trust-scorer.mjs`
- `scripts/validate-trust-scorer.mjs`
- `tests/security/trust-scorer.test.mjs`
- `docs/adr/0004-trust-scoring.md`

### F4. Adversarial Code Review — ✅ Solved

**Review phải kiếm được sự phê duyệt bằng evidence**

#### Vấn đề giải quyết
Agent review code của chính nó = rubber-stamp. Hoặc human reviewer chỉ đọc lướt rồi "LGTM" vì không có framework. Cả 2 dẫn đến bug và security hole lọt vào main.

#### Nguyên tắc cốt lõi (từ `adversarial-code-review/SKILL.md`)

```
"Đây KHÔNG phải polite rubber-stamp review: approval

  1. Làm sao tôi biết change này đúng?
  2. Edge case nào có thể break?
```

#### ✅ Đau giải quyết
"Agent rubber-stamps PRs" + "Human reviewer LGTM cảm tính". Framework ép structure câu hỏi rõ ràng, có categories (Blocker vs Suggestion vs Nit), có adversarial pass bắt buộc cho security-sensitive code.

### F11. Hooks Pack (Claude Code) — ✅ Solved

**6 hook points, default-deny, exit-code semantics**

#### Vấn đề giải quyết
Claude Code mặc định cho phép mọi tool call. Developer muốn safety net trước/sau tool execution nhưng không biết cách wire up.

#### 6 hook points (từ `claude-code-hooks-pack/SKILL.md`, 72 lines)

- **`PreToolUse`** — chạy TRƯỚC tool call, exit 2 = block (default-deny + allowlist)
- **`PostToolUse`** — chạy SAU tool call (secret scan, output validate)
- **`UserPromptSubmit`** — scan user prompt trước khi gửi Claude (injection detection)
- **`Stop`** — khi session dừng, snapshot state
- **`SessionStart`** — load context, set policy
- **`SessionEnd`** — audit flush, write security event log

**Exit-code semantics:** 0 = allow, 2 = block (stderr → user), other = error.

#### ✅ Đau giải quyết
"No safety net for tool calls" + "Agent exfiltrate qua Bash". Default-deny + ALLOWLIST_FILES = auditable narrow opt-outs thay vì global bypass. Inline `<!-- injection-allow:label -->` markers cho phép suppress specific patterns khi cần.

### F12. Guard Bypass Protocol — ✅ NEW v2.10.0+

**Opt-in offensive payload loader với audit trail**

#### Vấn đề giải quyết
Red team cần test hệ thống với payload tấn công thật. Nhưng nếu để payload tự động load = poisoned AGENTS.md hoặc skill có thể trigger bypass. Cần gated loader với audit trail.

#### Mechanism (`scripts/load-bypass-techniques.mjs`)

- Cần env var `VIBE_ENABLE_OFFENSIVE_TECHNIQUES=1`
- Cần `--authorization-ref` matching regex `^[a-zA-Z0-9_-]{6,64}$`
- Mỗi load attempt ghi vào `docs/security/bypass-load-attempts.log`
- Không load nếu thiếu 1 trong 2 điều kiện

#### ✅ Đau giải quyết
"Poisoned skill tự động load bypass catalog" + "Red team không có cách test hợp pháp". Defense = cả 2 điều kiện (env + auth-ref) + audit log. `vibe-bypass` là tính năng CÓ SẴN, cần bảo vệ.

#### Files thật trong repo
- `scripts/load-bypass-techniques.mjs`
- `docs/security/bypass-load-attempts.log`
- `skills/core/guard-bypass-protocol/SKILL.md`

## ❌ 5 Unsolved Pain Points (Critical)

Hội đồng 3 panels đồng thuận đây là những gì còn thiếu. Mỗi gap có impact và recommended fix.

### 1. No RAG-ingest sanitizer (LLM01 indirect injection via vector store)

`runtime/memory/vector-store.mjs` và `lessons-learned-db` ingest documents mà KHÔNG gọi `detectInjection()`. Một poisoned upstream skill, reference clone, hoặc lesson có thể plant indirect-injection vector bypass `validate-injection.mjs` (chỉ scan files at rest, không scan text at retrieval time). **Đây là attack surface LỚN NHẤT trong thực tế.**

**Fix:** `scripts/validate-rag-ingest.mjs` gọi `detectInjection()` on every document entering vector store + lessons. Refuse ingest on `severity=error`.

---

### 2. Trust scorer test chỉ check shape (security-critical gap)

`tests/security/trust-scorer.test.mjs` gọi `scoreSource(content, source)` và assert return object có `{ trust_class, risk_score }` thôi. Một scorer broken trả `{ trust_class: 'trusted', risk_score: 0 }` cho MỌI input sẽ PASS test này. Đây là security-critical code với zero behavioral verification.

**Fix:** Add tests với known-malicious patterns (Bidi chars, encoded payloads, social-engineering) phải receive lower trust score. Test `detectBypassLoop` catches circular trust escalation.

---

### 3. Framework tự bản thân nó 4.5% test coverage (credibility gap)

374 artifacts (152 skills + 121 commands + 128 templates), chỉ 17 có direct test. v2.16.0 master plan tự thú: "Engineering B+ (8.0/10) — Governance mature, behavior under-verified (4.6% test coverage)." Hỏi users tin quality discipline trong khi framework untested = credibility gap.

**Fix:** v2.17.0 target ≥40% test coverage. Make `npm run validate:all` part of user-facing quickstart.

---

### 4. No redactor behavioral tests cho 3 modes (security-critical gap)

`validate-redact.mjs` test pattern coverage, nhưng KHÔNG test 3 modes (`block` / `redact` / `log`) produce different outputs cho cùng input. Mode-dependent logic hoàn toàn untested at behavioral level.

**Fix:** Verify `block` throws / `redact` returns masked / `log` writes to side channel. `postTool` mode phải NOT mutate original input.

---

### 5. No supply-chain SCA gate (LLM03 + A06 blind spot)

`validate-licenses.mjs` cover license headers, `validate-provenance.mjs` cover attribution, NHƯNG không có CVE/vulnerability scanning. `package-lock.json` committed nhưng pinned-hash integrity không asserted bởi validator. Malicious transitive dep = A06 (vulnerable components) + LLM03 (training data poisoning via dep) blind spot.

**Fix:** Add `npm audit --omit=dev` hoặc `osv-scanner --lockfile=package-lock.json` vào `validate:all`. Fail build on `severity=high`.

### 10. Property test FP noise (68/382 systematic false positives)

## 🏛️ Architecture — 4 ADRs & 3-layer Defense

Foundation documents govern toàn bộ framework.

| ADR | Title | What it locks in |
|---|---|---|
| **ADR-0001** | Core/Optional Runtime Split | Framework = markdown docs/prompts/skills. Runtime là optional, không bắt buộc. → Developer không cài gì cũng dùng được. |
| **ADR-0002** | Runtime Freeze | Runtime scripts frozen (no expansion in current roadmap). `registry/runtime-freeze-allowlist.json` lists exceptions. |
| **ADR-0003** | Defense-in-Depth | 3 layers: DETECT (injection-counters) → CONTAIN (redactor) → RECOVER (regression tests). 18 OWASP LLM failure modes mapped. |
| **ADR-0004** | Trust Scoring (NEW v2.16.0) | Layer 0 trước cả 3 layers. Source-class gating + bypass-loop detection. Addresses meta-attack of attacker iterating. |

## 🚀 Top 10 Recommendations cho v2.17.0

Đã được 3-panel council consensus. Ranked theo Impact × Confidence.

### Tier 1 — High Impact, High Confidence (DO FIRST)

#### 1. RAG-ingest sanitizer
- **Effort:** Medium
- **Why:** Đóng LLM01 attack surface lớn nhất (vector poisoning). `scripts/validate-rag-ingest.mjs` calling `detectInjection()` on every document entering `runtime/memory/vector-store.mjs` and `lessons-learned-db`. Refuse ingest on `severity=error`.

#### 2. Auto-bind templates to commands
- **Effort:** Small
- **Why:** `/vibe-spec` auto-inject `templates/spec-template.md`, `/vibe-plan` inject `templates/plan-template.md`, `/vibe-tdd` inject minimal red-green checklist. `--dry-run` preview để user học output shape.

#### 3. Behavioral tests cho trust scorer + redactor
- **Effort:** Medium
- **Why:** Đóng 2 high-severity test gaps. Test known-malicious patterns receive lower trust scores. Test 3 redactor modes produce different outputs cho cùng input.

#### 4. SCA gate (npm audit / osv-scanner)
- **Effort:** Small
- **Why:** Đóng LLM03 + A06. Add `npm audit --omit=dev` hoặc `osv-scanner --lockfile=package-lock.json` to `validate:all`. Fail build on `severity=high`.

#### 5. Default-on Quality Shield cho non-trivial work
- **Effort:** Medium
- **Why:** Change `README.md:114-126` 8-step loop to insert Quality Shield as **required** cho changes >1 file hoặc touching behavior. Hiện tại sống trong doc riêng mà almost nobody tìm thấy.

### Tier 2 — High Impact, Medium Confidence

#### 6. `vibe doctor --goal "X"` skill-chain recommender
- **Effort:** Medium
- **Why:** Reads goal, queries `registry/skills.json` + `commands/manifest.json`, prints exact skill/command/template chain với clickable paths. Giải quyết "152 skills, không biết dùng cái nào" triệt để.

#### 7. Broaden secret-scan hook (Bash, WebFetch, NotebookEdit)
- **Effort:** Small
- **Why:** Hiện tại `post-tool-use-secret-scan.mjs` chỉ fires trên `Edit|Write|MultiEdit`. Secret có thể leak qua `Bash` (`cat .env`), `WebFetch`, `NotebookEdit`.

#### 8. End-to-end interactive demo
- **Effort:** Medium
- **Why:** `vibe demo invoicer-csv` takes one-line goal, runs spec → plan → implement → review → verify trên known starter repo, shows every output. Closes day-1 activation gap. `examples/react-nextjs-booking-workflow/` là static read; cần interactive runnable.

#### 9. Fix property test FP noise
- **Effort:** Small
- **Why:** Allowlist safe HTML tags (`<details>`, `<summary>`, `<table>`). Exempt `*template*` files từ `no_placeholder_content`. Drops 68/382 failures to ~10.

#### 10. Wire real parsers vào fuzz harness
- **Effort:** Medium
- **Why:** `property-test-runner.mjs:584` aspiration: "Future: pass generated inputs through actual skill/command/template parsers" → ship it. Hiện tại fuzz chỉ validate well-formed inputs, không exercise real parsing logic.

## 🎬 Verdict cuối cùng

**v2.16.0 = "Strong bones, thin seams."**

- **The bones are real.** Mỗi command và skill tôi mở đều có substantive content. Spec → plan → verify loop end-to-end và hoạt động trong markdown alone. Security wiring (Trust Scoring, RTL 100%, redactor) là cải tiến quan trọng nhất và thực sự differentiated so với framework khác.
- **The seams are weak.** Template-to-command binding thiếu. Default loop bypasses các layer mạnh nhất (Quality Shield, adversarial review). Skill discovery requires a search tool user không biết. Framework tự nó ship ở ~4.5% test coverage. Và cho non-Claude-Code users (Cursor, Gemini), path vẫn là "manually paste CLAUDE.md vào rules".
- **The ceiling is high** (framework *có thể* giải quyết hard problems). **The floor — what a developer experiences in their first hour — has not been raised as much as the marketing implies.**

**Recommended next sprint (v2.17.0):** Tier 1 ở trên. 5 items, 1 sprint. RAG sanitizer + template auto-bind + behavioral tests for security + SCA gate + default-on Quality Shield. Single sprint đó sẽ close 5 of 6 CRITICAL gaps.
