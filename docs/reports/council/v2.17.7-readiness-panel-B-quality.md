## Gate-by-Gate Reality Audit

Audited each of the 12 gates in `npm run validate:all` against four questions:
1. Does it **fail** on a real bug class (crash, syntax error, broken import)?
2. Or does it **fail** on process theater (missing version, naming drift, commit trailer format)?
3. What is its false-positive cost?
4. What's the bug→gate ratio?

### ✅ REAL BUG CATCHERS (4 of 12)

| Gate | Real Bug Class Caught | FP Rate | Verdict |
|------|----------------------|---------|---------|
| **validate-imports.mjs** (L132-141) | Broken imports → runtime crashes. Scans 139 .mjs files, 530 imports. **Binary pass/fail.** | Near-zero | ★ **MVP gate.** Catches actual CannotFindModule errors before CI. |
| **validate-injection.mjs** (L206-213) | Prompt injection payloads in shipped artifacts. Blocks on error-severity patterns. | Low (allowlist + inline markers) | ★ Security gate that blocks real harm. |

## Bug Surface NOT Covered

After reading every validator, the autopilot runtime, and the test suite, these are the gaps where AI-generated code ships bugs that NO gate catches:

### 1. No Linter (ESLint/Prettier/Biome)
Zero lint tooling in the entire repo. No `.eslintrc`, `.prettierrc`, `biome.json`, or `tsconfig.json`. The entire quality engine is regex-based.  
**Bug class missed:** Unused variables, unreachable code, broken async patterns, implicit globals, stale closures.  
**Cost:** Each of these is a runtime crash waiting to happen. Mid-tier models (Codex, Claude Sonnet) produce these daily.

### 2. No Type Checker
`validate-typecheck.mjs` is promising but regex-based and **non-blocking** (line 141: `process.exit(0)`). It only checks 6 misspellings and duplicate params.  
**Bug class missed:** Wrong types passing through, null references, missing returns, undefined access.

### 3. Property Tests Don't Execute Code
`property-test-runner.mjs` (660 lines) generates random input combinations and checks structural invariants (file exists, has heading, has purpose section). It **never evaluates the actual skill content.** The "fuzz testing" (line 580-603) only validates input shapes, not behavior.  
**Bug class missed:** Broken workflow instructions, missing tool calls, hallucinated commands.  
**Evidence:** 80% pass threshold in `validate-property-tests.mjs` — but what does "pass" mean if we never execute?

### 4. No Runtime Integration Tests Against Actual Agents
The 14 `test-runtime-*` files test component boundaries (enforcement, leases, envelopes, tool contracts) but **never simulate an actual agent loading and following a skill**.  
**Bug class missed:** Skills that reference non-existent tools, commands that hallucinate MCP endpoints, templates that crash when rendered.

### 5. No Dead Code Detection
No tree-shaking, no `ts-prune`, no `unimported`. Skills accumulate cruft. The trim from 152→115 skills happened in v2.17, but **unused exports within remaining files are invisible.**  
**Bug class missed:** Function definitions that shadow real APIs, dead code confusing agents.

### 6. No Runtime Error Log Mining
The autopilot records errors (line 127-131 of `loop.mjs`) but there's no gate that parses `.vibe/` runtime logs for crash patterns and feeds them back into validation.

### 7. validate-secrets.mjs Has Ghost FPs
The `Generic-credential` pattern (line 38 of `runtime/core/privacy.mjs`) currently matches documented credential examples in:
- `docs/workflows/runtime-mcp-server.md` lines 79, 121, 135, 145
- `tests/runtime/runtime-mcp-auth.test.mjs` line 288

These are legitimate documentation. The allowlist regexes (lines 34-54 of validate-secrets.mjs) cover `docs/reports/` but miss `docs/workflows/` and `tests/runtime/`. **Result: the gate fires 5 FPs every run.** The maintainer ignores them → the gate is de-facto disabled.

## Recommendations: Cheap Gates That Catch What Models Still Get Wrong

### Tier 1 (10-30 min each, immediate value)

1. **Make validate-typecheck.mjs blocking** — Change line 141 from `process.exit(0)` to `process.exit(warnings.length > 0 ? 1 : 0)`. 5-minute fix. Catches `readdFile`/`exsitsSync` before they ship.

2. **Install eslint + eslint-plugin-node** — 10 minutes (`npm install --save-dev eslint`, create `.eslintrc.json` with `{ "extends": ["eslint:recommended"], "env": { "node": true, "es2022": true } }`). Catches unused variables, unreachable code, broken promises.

3. **Fix the 5 secrets FPs** — Add `docs/workflows/runtime-mcp-server.md` and `tests/runtime/runtime-mcp-auth.test.mjs` to the ALLOWLIST_PATHS in validate-secrets.mjs. 5-minute fix restores gate credibility.

### Tier 2 (1-2 hours each)

4. **Dead export analysis** — Run `npx unimported` or write a 50-line script that imports every `.mjs` file and checks all exports are consumed. Catches AI "artifact" exports that models leave behind.

5. **Property test runner that actually evaluates skills** — Instead of just checking `SKILL.md` exists, inject the skill prompt into a minimal agent and assert on output structure. 2-hour effort, enormous signal.

### Tier 3 (4+ hours, but highest long-term value)

6. **Runtime error gate** — Parse `~/.vibe/logs/` for tool-call failures after each session. Map `ToolExecutionError` → skill → validation fail. This closes the feedback loop.

7. **MCP tool-name drift gate** — `validate-injection.mjs` scans `.mcp.json` for injection patterns but not for tool-name drift (tool declared in config but not implemented in runtime). Simple diff check would catch this.

## Summary

**4 of 12 gates catch real bugs** (validate-imports, validate-injection, validate-secrets, and potentially validate-typecheck if made blocking). **6 of 12 are pure process theater** — they fail on hygiene violations, not runtime bugs. The biggest gap is **no linter at all**: no ESLint, no TypeScript, no Prettier. Mid-tier AI models produce unused variables, broken async patterns, and unreachable code every session, and zero gates catch these.

**The highest-ROI fix is a 5-minute change** to make `validate-typecheck.mjs` blocking (currently always exits 0, rendering its pattern checks advisory). Combined with a 10-minute ESLint setup, this would close the biggest class of AI-shipped bugs.

**Gate credibility issue:** `validate-secrets.mjs` fires 5 false positives every run (documented credentials in workflow docs and tests). The allowlist regexes don't cover these paths. Maintainers learn to ignore the output, which means real credential leaks could slip through unnoticed.

**Property tests are well-intentioned but don't execute code.** The `property-test-runner.mjs` checks structural invariants (file exists, has heading) but never evaluates skill content against a model. The 80% pass threshold is meaningless when nothing actually runs.

**Bottom line:** This repo has invested heavily in structural validation (12 gates!) but under-invested in execution-based quality. The autopilot loop (`runtime/autopilot/loop.mjs`) does handle errors gracefully (line 127-131: errors increment counter, loop continues), but there's no gate that aggregates those errors and blocks PRs. The missing piece is a runtime feedback loop that converts agent-crash signals back into validation gates.
