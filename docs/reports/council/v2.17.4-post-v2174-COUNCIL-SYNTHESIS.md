## Critical Gaps (Ranked by Severity)

### 🔴 C1: README/FAQ stat chaos undermines newcomer trust

**Mô tả:** README claims 113, 115, AND 116 commands in different sections. FAQ says "33 gates" when validate:all runs 11. FIRST-WORKFLOW.md says "26 gates." A newcomer sees contradictory numbers and loses trust in the documentation.

**Fix:** (1) Audit all stat claims in README.md, FAQ.md, FIRST-WORKFLOW.md. (2) Add `validate:stat-sync.mjs` CI guard that checks README "Current release" stats against actual disk counts.

### 🔴 C2: MCP server has no authentication

**Mô tả:** `runtime/mcp/server.mjs` uses StdioServerTransport with zero caller verification. Any local process or modified `.mcp.json` gains access to 16 tools including `autopilot.start` (which can define arbitrary policy rules including `file.write` and `shell.command`).

**Fix:** Add local-token auth to MCP server: generate random token on start, require it in every `CallToolRequestSchema` handler. Lightweight (no SDK dependency).

### 🟡 C3: validate:no-deprecated-commands misses .claude-plugin/ and skills/

**Mô tả:** `.claude-plugin/plugin.json:199,236` contains stale `vibe-parallel-explore` and `vibe-specify` refs. `skills/core/clarify-before-code/SKILL.md:77` references `commands/vibe-specify.md`. The CI gate never scans these paths.

**Fix:** Add `.claude-plugin/` and `skills/` to the gate's target list.

### 🟡 C4: 3 overlapping PR-comment workflows waste CI minutes

**Mô tả:** `pr-quality-comment.yml`, `quality-gates.yml`, and `vibe-quality-gate.yml` all post similar PR comment summaries and each re-runs `validate:all` independently.

**Fix:** Consolidate into one workflow; have the others skip PR comment posting.
