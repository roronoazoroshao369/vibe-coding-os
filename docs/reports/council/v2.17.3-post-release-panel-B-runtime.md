## Autopilot GC Audit (code review of `gcSessions`)

`runtime/mcp/autopilot-tools.mjs:107-134`:

| Check | Status | Notes |
|---|---|---|
| (a) Missing state dir | ✅ | `if (!existsSync(dir)) return 0;` at L109 — early-returns cleanly. |
| (b) Corrupt JSON files | ✅ | `try { JSON.parse } catch { unlink + removed++ }` at L116–128. Quarantines without crashing. |
| (c) TTL calculation | ✅ | `now - new Date(session.createdAt).getTime() > ttlMs` at L119–120. **`createdAt` is an ISO string** set in `autopilot.start` (L195) as `new Date().toISOString()`. If `createdAt` is missing/NaN, `new Date(undefined).getTime()` returns `NaN`, and `now - NaN > ttlMs` is `false` — so a missing-field file is **silently kept**, not deleted. See edge case E1 below. |
| (d) Called from correct handlers | ✅ | Called from `autopilot.start` (L218) and `autopilot.list` (L273). `autopilot.status` correctly skips GC (read-only). `autopilot.stop` correctly skips GC (single-file delete). |
| (e) Audit log | ✅ | Writes `audit.log` line when `removed > 0` (L131). No log on no-op GC runs — fine, keeps the log lean. |

**GC wiring is correct, but the corrupt-JSON branch is broader than it looks**: any file ending in `.json` in the dir gets read and parsed (L114 filter is just extension). If someone drops a non-session JSON file in there, it will be deleted on the next GC. That may be the desired behavior, but it's not documented.

## Unit Tests Quality Assessment

`runtime/autopilot/__tests__/policy.test.mjs` — 14 tests, 5 suites, all green. **Mostly meaningful, not shape-only.**

**Strengths:**
- Genuine behavior coverage: max_calls enforcement, wildcard prefix vs. exact match, `*` universal wildcard, `resetCounters` lifecycle, constructor validation (risk/approval enum).
- Uses `assert.throws(/regex/)` for constructor validation — not just `assert.throws()`.

**Edge cases NOT covered** (rank-ordered by risk):
- **T1 (HIGH):** `max_calls: 0` — undefined behavior. JSON Schema in `autopilot-tools.mjs:173` says `minimum: 1`, but `policy.mjs:82` accepts any integer. `normalizeRule` stores `max_calls=0`; `allows()` returns `false` immediately (`current(0) >= max_calls(0)`). Test should pin this down (block everything? throw? document as invalid?).
- **T2 (MED):** Reserved shorthand patterns (`action: 'write'`, `'network'`, `'dangerous'`, `'all'`) at `policy.mjs:48-61` are **never tested**. The `expandReservedPattern` branch is dead code under test.
- **T3 (MED):** Concurrent `recordCall()` — single-threaded JS makes this hard, but `Promise.all` simulation is cheap. The `_callCounts` map is not concurrency-safe in principle (a logged race when the policy is shared across awaits).
- **T4 (LOW):** `requiresApproval` is not tested for the `block` case (returns `false` — a counter-intuitive but real semantic).
- **T5 (LOW):** `log()` doesn't assert the `unlimited`/∞ rendering for `Infinity` max_calls (the `*` test uses `max_calls: 3` only).
- **T6 (LOW):** Default risk/approval in `normalizeRule` (`risk='medium'`, `approval='auto'`) — never asserted; a missing field silently defaults, which is a footgun.

## Recommendations

1. **Fix E1 (HIGH):** In `gcSessions`, when `createdAt` is missing or unparseable, treat it as a corrupt file and delete (mirror the JSON.parse failure branch). This makes GC behavior consistent and predictable.
2. **Fix E3 (MED):** Bump `SERVER_VERSION` in `runtime/mcp/server.mjs:22` to `'2.17.3'` to match `package.json`, and add a CI check that fails the `validate:autopilot` script when they drift.
3. **Expand tests (T1, T2, T4):** Add cases for `max_calls: 0`, reserved-shorthand expansion, and `requiresApproval` for `block`. These are behaviorally important and the current suite is shape-only on these branches.
4. **Tighten GC scope (E2):** Whitelist session filename pattern (e.g. `^[A-Za-z0-9_-]+\.json$`) and ignore any other `.json` in the state dir. Document the assumption in the file header.
5. **Remove dead import (E4):** Drop `createHash` from `policy.mjs:10` unless it's being prepared for a follow-up feature (in which case, add a TODO and a test).
6. **Document the SDK fallback (B2):** Note in `docs/workflows/runtime-mcp-server.md` that `--tools` shows the union of registered tools and that adapter-level allowlists are only enforced on the live `CallTool` path.
7. **CI polish (C1, C3):** Add `cache: 'npm'` and an `engines` cross-check (`node -e "..."` asserting major version) to keep the workflow honest with `package.json`.

**Verdict:** The v2.17.0→v2.17.3 fixes hold up under scrutiny. Tool wiring is fully synchronized, GC is correctly wired, CI is valid, and tests are mostly meaningful. The one real bug is **E1** (silent keep of corrupt files with missing `createdAt`); everything else is hardening.
