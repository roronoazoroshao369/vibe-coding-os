## Length Audit: Token Counts

### Full Corpus Statistics

| Metric | SKILL.md | commands/*.md |
|--------|----------|---------------|
| **File count** | 115 | 115 |
| **Total lines** | 10,570 | 6,497 |
| **Average lines/file** | 92 | 57 |
| **Median lines/file** | 82 | 51 |
| **Shortest** | 48 | 7 |
| **Longest** | 424 | 187 |
| **~Token total (if all loaded)** | ~99k | ~50k |

**Combined corpus: ~149k tokens.** This exceeds every model's context window (32k for Qwen3-30B, 128k for Llama 3.3 70B, 200k for GPT-OSS). No model — not even Sonnet 4.5 — can load all 115 skills + 115 commands in one pass.

### What a Mid-Tier Model Actually Loads

A typical mid-tier session loads:

- `CLAUDE.md` (50 lines, ~500 tokens)
- 1 command (median 51 lines, ~500 tokens)
- 1 skill (median 82 lines, ~900 tokens)
- 1 template (varies)
- User conversation history

**Estimated per-session token budget: ~3-5k tokens** for core artifacts. This is manageable for any 32k context model.

### The REAL problem: cross-referencing

Skills reference each other extensively. `spec-first-development/SKILL.md` references 6 other core skills. `karpathy-engineering-discipline/SKILL.md` references 3 sibling skills. If a mid-tier model needs to follow all links to understand a single skill, context explodes from 1k → 6k+ tokens.

## Pain Points Specific to Non-Top-Tier Models

### 1. Context window pressure from frontmatter + bilingual content

Every SKILL.md has YAML frontmatter (name, version, introduced_in, last_reviewed, category, tags, status). This adds ~60-120 tokens of metadata per skill that a human never reads but the model must parse.

Many files include Vietnamese (`Ghi chú tiếng Việt`) sections that duplicate the English content. This adds 20-40% overhead to every file. Mid-tier models process both languages, consuming context budget for low-value content.

### 2. The "Self-Auditing Paradox"

The framework relies on self-review skills (`verification-before-done`, `self-review-before-response`, `quality-execution-contract`) that ask the model to verify its own output. A mid-tier model that cannot detect its own errors (hallucinated APIs, missed edge cases) will pass its own audit with false confidence. The prior trim-audit (v2.17.0 triage council) flagged this: "The LLM is the thing making the mistakes."

### 3. No explicit mid-tier configuration in CLAUDE.md

`CLAUDE.md` (50 lines) is the entry point for the assistant. It does NOT mention:
- "If you are a mid-tier model, load only one skill at a time"
- "Skip the orchestration commands if context is tight"
- "Start with tiny/small tier flows"

Without this, a mid-tier model loads everything and fills its context.

### 4. Adaptive Flow classification requires meta-reasoning

The 5-tier classification (tiny/small/medium/large/risky) asks the model to judge its own task risk. Mid-tier models consistently under-classify risky work ("it's just one file, it's tiny") and over-classify trivial work ("this touches auth, make it risky"). This defeats the purpose.

### 5. Command branchiness

Commands like `vibe-flow` (89 lines) contain conditional routing: "If tiny → implement directly. If small → one-line spec note. If risky → large flow + characterization tests + rollback plan." Mid-tier models parse branching prompts poorly — they tend to execute only the first matching condition or skip negative conditions.

### 6. No token budget enforcement

`skills/meta/context-budget/SKILL.md` (137 lines) is a meta-skill that coaches the model to audit its own context usage. This is a **meta-cognitive ask** — exactly the kind of recursive reasoning that mid-tier models handle worst. The skill itself flags 400+ lines as "split-or-trim candidate" but the repo still contains 424-line files.

## Recommendations for Mid-Model Accessibility

### Immediate (can be done today)

1. **Add mid-tier mode hint to CLAUDE.md** — 2 lines: "If using a mid-tier model (< 100k context), load ONE command + ONE skill per task. Skip vib-flow; use vibe-spec directly. Avoid orchestration commands."

2. **Strip Vietnamese bilingual sections from core SKILL.md files** — Move `Ghi chú tiếng Việt` to a separate `SKILL.vi.md` file. Saves 20-40% tokens per file for non-Vietnamese users.

3. **Create a "mid-tier default flow"** — A new `docs/MID-TIER-FLOW.md` that hardcodes the simplest path: `vibe-spec → vibe-plan → vibe-implement → vibe-verify`. No tier classification. No Adaptive Flow. No Smart Adapt. Give mid-tier models a straight-ahead track.

4. **Collapse YAML frontmatter boilerplate** — Remove `version`, `introduced_in`, `last_reviewed` from production consumption; serve a stripped version. Saves ~60 tokens per skill × 115 skills.

5. **Add `CLAUDE-LITE.md`** — A 15-line version of CLAUDE.md with just the minimal contract: "Define goal → write spec → plan → implement → verify." No anti-patterns, no reference intelligence, no proficiency levels.

### Short-term (next release)

6. **Auto-split guard-bypass-protocol** — The 424-line file already violates the repo's own 400-line threshold. Split into `guard-bypass-intro/SKILL.md` (48 lines) + technique-specific sub-skills.

7. **Add model-agnostic default in `model-aware-config-guide.md`** — Document a specific `mid-tier-lean` profile that runs minimal gates and assumes 32k context. Currently profiles only distinguish claude-sonnet vs gpt-4o-mini patterns — add a "mid-32k" capability tier.

8. **Reduce cross-referencing** — Inline essential sub-concepts rather than linking to other skills. Mid-tier models don't reliably open referenced files. Each skill should be self-contained for basic usage.

### Strategy note

The repo's Vietnamese strategy doc at `docs/vi/strategy-and-roadmap.md` already has the right formula:

> **Agent Quality = Model Capability × Context Quality × Workflow Discipline × Verification Feedback**

The repo optimizes for Workflow Discipline and Verification Feedback. To make mid-tier models work, it MUST also optimize for **Context Quality** (smaller, self-contained prompts) and adjust expectations for **Model Capability** (less self-auditing, more structured templates). The bones are good — the trim is the opportunity.

## Summary of Findings

| Dimension | Verdict |
|-----------|---------|
| Day-1 install & first workflow | 🟢 Functional. ~15 min for CLI-savvy, ~30 min for newcomers. Plugin path is smoothest. |
| SKILL.md atomicity | 🟡 Mostly good (median 82 lines). 6 files exceed 150 lines; 1 outlier at 424 lines. |
| Command prompt length | 🟢 Good (median 51 lines). 3 commands exceed 130 lines — manageable for core workflow. |
| Full corpus context load | 🔴 149k tokens — no model can load everything. But the normal workflow loads only 3-5k tokens. |
| Model hints / tier guidance | 🟢 Model-aware config exists. Lean/standard/heavy profiles included. Smart Adapt has model-weakness-memory. |
| Mid-tier explicit support | 🟡 Strategy doc mentions mid-tier, but no CLAUDE.md annotation, no token budget enforcement. |
| Prior report overlap | 🟢 v2.17.6 covered MCP auth docs gap (resolved). v2.17.7 hardening covered security regression gate. Both are distinct from this mid-tier model audit. |

**Bottom line:** Yes, a mid-tier model CAN use this repo effectively — but only for the short, atomic skills (60-90 lines) with the core workflow commands (vibe-spec, vibe-plan). It will break on orchestration, security, and multi-skill workflows. Add a mid-tier mode hint to CLAUDE.md and a MID-TIER-FLOW.md doc, and Qwen3 30B / Llama 3.3 70B users will have a reliable experience today.
