## 2. Strengths

1. **Defense-in-Depth pattern (ADR-0003) is concretely implemented**, not aspirational: Layer 1 (`injection-counters.mjs` with 30+ regexes, unicode normalization, base64 decoder, entropy), Layer 2 (`redactor.mjs` with 30 secret patterns × 3 pipeline modes: postTool / postSession / postPublish), Layer 3 (`tests/security/regression.mjs` + `baseline.json` 100% / 0% FP at last run, CI-gated fail-build on regression).
2. **Layer 0 Trust Scoring (ADR-0004, v2.16.0)** adds source-class gating (trusted / read-only / isolated) and bypass-loop detection — newer than most OWASP boilerplate and addresses the *meta* failure mode of an attacker iterating to find a working payload.
3. **Two complementary injection scanners** with non-overlapping scopes: `runtime/core/injection-patterns.mjs` (portable, scans shipped artifacts, two severities: error/warn) vs `security/defense/injection-counters.mjs` (richer, in-process `detectInjection` API). Use of two-severity model deliberately avoids false-confidence that blocks legitimate docs.
4. **Default-deny pre-tool hook** + explicit `ALLOWLIST_FILES` + inline `injection-allow:<label>` suppression = auditable, narrow opt-outs rather than global bypass.
5. **Gated offensive-payload loader** (`load-bypass-techniques.mjs`) prevents a poisoned `AGENTS.md` / skill from auto-loading the bypass catalog — needs both env var AND a structured authorization ref.
6. **Bidi/unicode/homoglyph** handling covers the OWASP LLM04 hardest cases that most repos miss.

---

## 3. Critical Gaps (Top 5)

1. **No runtime RAG/context sanitization.** `secure-coding-checklist` recommends "Sanitize retrieved documents (RAG) for adversarial content" (LLM08), but `runtime/memory/` (vector store, embeddings, lesson-exchange) has no equivalent of `detectInjection()` invoked on ingest. A poisoned upstream skill, reference clone, or lesson could plant indirect-injection vectors that bypass `validate-injection.mjs` (which scans files at rest, not text *at retrieval time*). **High impact**, since this is the dominant real-world LLM01 attack surface.
2. **No semantic / model-based jailbreak detection.** Lexical regexes catch `DAN`, "you are now", "ignore previous instructions" — but paraphrase, role-play framing in non-English, or compressed payloads (`base64` of "ignore…", Cyrillic "ignоre") require per-pattern maintenance. `homoglyph` regex exists but only Cyrillic/Greek, not confusable punctuation or mathematical alphanumeric symbols (U+1D400–U+1D7FF). Hallucination library names (LLM09) entirely unchecked.
3. **`secure-coding-checklist` is documentation, not enforcement.** It maps OWASP A01–A10 + LLM01–LLM10 beautifully, but the skill is *invoked by humans/agents* during review. There is no `scripts/validate-secure-coding-coverage.mjs` checking that a touched trust-boundary file actually has a matching gate entry. Recommend a gate analogous to `validate-security-command-coverage.mjs`.
4. **No supply-chain SCA gate.** `validate-licenses.mjs` + `validate-provenance.mjs` cover license + attribution but not CVE/vulnerability scanning (npm audit, `osv-scanner`, `socket`). `package-lock.json` is committed but unpinned-hash integrity is not asserted by a validator. A malicious transitive dep = LLM03 + A06 blind spot.
5. **Default-deny hook is single-tool-match (`Edit|Write|MultiEdit` only).** `post-tool-use-secret-scan.mjs` only fires on those three matchers, so a secret can leak through `Bash` (`cat .env`), `WebFetch` (paste into response), or `NotebookEdit`. `pre-tool-use-default-deny.mjs` is `matcher: "*"` but the secret redactor post-hook is not — same-layer-as-the-leak defense is missing for non-Edit tools.

### Medium Gaps
- **Hallucination (LLM09):** no grounding/fact-check gate; relies on reviewer.
- **Cross-turn state poisoning:** `runtime/memory/` persists across sessions; cross-session injection via stored lessons is not scanned on load.
- **Unbounded consumption (LLM10):** no token-bucket or request-rate enforcement in `.claude/settings.json` or runtime.
- **Output schema validation (LLM05):** recommended by checklist but not enforced by a `validate-output-schema.mjs` equivalent.
- **System-prompt integrity (LLM07):** recommended signing/hashing in checklist, not implemented.
- **Canary corpus poisoning risk** (acknowledged in ADR-0003): 90-day rotation, but no automated rotation/reminder.
- **False-positive rate tracking** is in ADR but no `docs/security/redact-fp-rate.md` quarterly report observed.
- **`trust-scorer.mjs` heuristics are 12 keyword regexes** (curl, axios, fetch) — trivially defeated by `f​e​tch` with zero-width chars unless `normalizeUnicode` is invoked first (it is, but only at detection time, not at ingest).

## 4. Recommendations for v2.17.0

1. **Add `scripts/validate-rag-ingest.mjs`** that calls `detectInjection()` on every document entering `runtime/memory/vector-store.mjs` and `lessons-learned-db`. Refuse ingest on `severity=error`. Closes Gap #1 (biggest).
2. **Wire `detectInjection()` into `user-prompt-submit-injection-scan.mjs`** so the live prompt path uses the same 30-pattern detector as the corpus scanner; currently two parallel implementations can drift.
3. **Add `scripts/validate-secure-coding-coverage.mjs`** that flags any file under a trust boundary (handlers, shell calls, MCP tools) without a matching `secure-coding-checklist` invocation comment. Closes Gap #3.
4. **Add SCA gate** (`npm audit --omit=dev` or `osv-scanner --lockfile=package-lock.json`) to `validate:all`; fail build on `severity=high`. Closes Gap #4.
5. **Broaden `post-tool-use-secret-scan.mjs` matcher** to include `Bash`, `WebFetch`, `NotebookEdit`. Or move secret scan to `UserPromptSubmit` + `SessionEnd` for cross-tool coverage.
6. **Add semantic/embedding-based detector** behind a feature flag for the highest-risk categories (DAN, exfiltration directives) — keep regex fast-path as default, escalate ambiguous cases.
7. **Output schema validation module** (`validate-output-schema.mjs`) wired to `.claude/hooks/post-tool-use-*` for any tool returning LLM-generated content.
8. **Token-bucket for LLM10** + per-session request cap in `runtime/task-state-machine.mjs`.
9. **Schedule quarterly canary-corpus rotation** + emit reminder from `quality-trend-dashboard.mjs`.

---

## 5. Verdict

v2.16.0 has **mature, layered defenses against lexical/structural AI failure modes** (injection, secrets, tool abuse, bidi, homoglyphs, bypass auth) and an unusually thoughtful **trust-scoring meta-layer (ADR-0004)**. Coverage is **strong on input/containment** but **thin on output/runtime/RAG vectors** and **entirely documentation-driven on the "soft" OWASP LLM categories** (LLM07, LLM09, LLM10). A semantically-aware attacker who paraphrases or targets retrieved context would find exploitable surface. Recommend prioritizing the RAG-ingest sanitizer and SCA gate for v2.17.0.
