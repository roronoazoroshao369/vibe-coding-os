## New Findings (not in prior audit)

### N1 — Real Bug: gcSessions NaN keeps corrupt files (HIGH)
**Source:** Panel B, edge case E1
`runtime/mcp/autopilot-tools.mjs:119` — when `createdAt` is missing or malformed, `new Date(undefined).getTime()` returns `NaN`. The comparison `now - NaN > ttlMs` is always `false`, so the file is **never deleted**. This contradicts the explicit corrupt-JSON-delete branch at L124-127.
**Fix:** Treat missing/unparseable `createdAt` as corrupt → delete.

### N2 — 7+ command files still reference deprecated `vibe-specify` (HIGH)
**Source:** Panel A, Pain Point 1
`vibe-flow.md` (4 refs), `vibe-plan.md`, `vibe-align.md`, `vibe-tasks.md`, `vibe-brief.md`, `vibe-checklist.md`, `vibe-analyze.md` — all still point to `commands/vibe-specify.md`.
**Fix:** Bulk replace `commands/vibe-specify.md` → `commands/vibe-spec.md` in all 7 files.

### N3 — Version drift in 3 files (MEDIUM)
**Source:** Panel C + Panel B
- `.claude-plugin/plugin.json` → `"version": "2.17.1"` (should be 2.17.3)
- `plugins/manifest.json` → `"version": "2.17.1"` (should be 2.17.3)
- `README.md` → "Current release (v2.17.0)" (should be 2.17.3)
- `runtime/mcp/server.mjs:22` → `SERVER_VERSION = '2.17.0'` (should be 2.17.3)
**Fix:** Bump all 4 to 2.17.3.

### N4 — commands/manifest.json has orphan entries (MEDIUM)
**Source:** Panel A, Pain Point 2
`commands/manifest.json` still lists `vibe-parallel-explore` and `vibe-specify` as active. Also `count: 115` but disk has 115 excluding README — so count is right but entries are stale.
**Fix:** Remove deprecated entries, regenerate from disk.

### N5 — 7 dead validate-*.mjs scripts (LOW)
**Source:** Panel C
`validate-no-orphan-todos`, `validate-pack-schemas`, `validate-release-metadata`, `validate-roadmap-status`, `validate-rtl-coverage`, `validate-security-command-coverage`, `validate-trust-scorer` — none wired to any npm script.
**Fix:** Either wire them into validate:all or delete.

### N6 — Dead import in policy.mjs (LOW)
**Source:** Panel B
`runtime/autopilot/policy.mjs:10` imports `createHash` from `node:crypto` but never uses it.
**Fix:** Remove unused import.

## Verdict

The v2.17.0→v2.17.3 cycle was **the right work done in the right order**. Critical bugs were fixed first (Tier 1: v2.17.1), governance strengthened (Tier 2: v2.17.2), hygiene completed (Tier 3: v2.17.3), and automation added (Tier 4: v2.17.3). The 84% closure rate is strong for 4 releases in 2 days.

**What remains is not dangerous — it's messy.** The deprecated command residue is cosmetically bad (newcomer confusion) but not functionally broken (deprecated files still exist on disk). The version drift is embarrassing but not exploitable. The dead validators are confusing but harmless.

**The one thing that IS dangerous** is the gcSessions NaN bug (N1) — it means session files with corrupt timestamps will accumulate indefinitely, silently eating disk. This should be fixed before the next tag.

**Recommendation: Ship v2.17.4 as a focused cleanup release** (N1 + N2 + N3 + N4 + ROADMAP + dead-code cleanup) within 1 day, then shift focus to bus factor (community work, not code).
