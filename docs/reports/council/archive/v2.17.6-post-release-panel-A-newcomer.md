# v2.17.6 Post-Release Panel A — Newcomer / Day-1 UX Audit

**Auditor:** Panel A (Newcomer / First-time Developer)
**Release audited:** v2.17.6 — Tier 2 MCP Security Hardening
**Repo root:** `/home/devops/vibe-coding-os`
**Date:** 2026-06-22

## TL;DR

v2.17.6 is **welcoming for newcomers** with one documentation gap. The README value proposition is clear ("workflow discipline for AI coding"), the FAQ covers real questions, and the `vibe-plan → vibe-spec → vibe-tasks → vibe-verify` flow is documented and discoverable. The main friction point is **MCP auth has no end-user docs** — the new token-gated handshake shipped in code but docs/workflows/runtime-mcp-server.md only describes the pre-auth flow (6 basic tools). A newcomer cannot discover how to set up the auth token, what `MCP_AUTH_TOKEN` does, or that `~/.vibe/mcp-token` is auto-generated. This is a docs-only gap, not a code gap.

## 1. First Impressions

### 1.1 README value prop (first 60 seconds)

The opening line — *"Workflow contract first. Runtime optional. Human intent stays sovereign."* — is philosophically clear but jargon-heavy for a newcomer. The `### Why this matters` section (3 lines) is excellent: it explains the problem (speed without structure = scope creep) and the solution (verification gates + engineering practices) in plain English.

**Verdict:** A developer who reads lines 1-20 will understand what this repo IS. A developer who stops at line 6 will leave confused.

### 1.2 What's new section

Lines 20-57 cover v2.17.0 trim (5 tiers) with clear emoji markers (🗑, 🔀, ✂️, 🤖, 🎭). The "What's new in v2.17.6" line (line 18) is a single line: "Tier 2 MCP Security Hardening — token-gated handshake + runtime injection scanning." This is correct but gives no detail on what a user should DO with this info.

### 1.3 FAQ (`docs/FAQ.md`)

JSON-LD FAQPage schema at line 5-6 is correct and SEO-optimized. The 8 Q&As cover: what it is, what it isn't, difference from LangChain/Cursor/Copilot, install path, and "is it a runtime" (explicitly no per ADR 0002).

**One issue:** Q3 says "the runtime is frozen" which contradicts the actual runtime activity (autopilot, MCP server, task store). This FAQ answer is stale from v2.16.0 trim.

## 2. Onboarding Friction

### 2.1 Entry point (`vibe plan`)

The flow `vibe-plan → vibe-spec → vibe-tasks → vibe-implement → vibe-verify → vibe-review → vibe-merge` is documented in `docs/workflows/constitution-to-spec-to-plan.md` and in `docs/FIRST-WORKFLOW.md` (if it exists — check).

### 2.2 MCP setup path

`docs/workflows/runtime-mcp-server.md` describes:
1. Add SDK to package.json
2. Register in `.mcp.json`
3. 6 basic tools available

**MISSING:** The docs don't mention:
- `MCP_AUTH_TOKEN` env var
- Auto-generated token at `~/.vibe/mcp-token`
- The auth handshake requirement (`_mcp.auth.verify` first)
- Injection scanning behavior (blocking vs advisory)
- How to configure auth in practice

**Impact:** HIGH — a newcomer using Claude Desktop will not know why their MCP tools aren't working (they'll hit "Not authenticated" without understanding the fix).

### 2.3 `runtime-install.mjs` docs

`docs/workflows/runtime-install.md` is well-written: clear flags table, idempotent default, Vietnamese translation included. This is a positive friction-reducer.
