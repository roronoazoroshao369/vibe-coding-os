# Panel A — Newcomer UX Audit (v2.17.0 Post-Release)

**Date:** 2026-06-22  
**Scope:** First-time user simulating a 10-step realistic workflow from `git clone` to first spec done.  
**Method:** Fresh clone in `/tmp`, trace each onboarding step with actual command execution, file inspection, and stale-reference sweep across commands/, docs/, templates/, examples/, and registries.

---

## Executive Summary

A newcomer who clones v2.17.0 today can complete a basic `spec → plan` loop via the CLI, but the path is cluttered with stat-mismatched README lines, 14+ stale references to deleted/merged skills, a `commands/manifest.json` that still lists orphan and deprecated commands, and a `FIRST-WORKFLOW.md` that assumes `npm link` privileges. The CLI `vibe doctor` and `vibe init` both work on a fresh clone, but `vibe verify`, `vibe review`, `vibe merge`, and `vibe tasks` are **missing from the CLI** — they exist only as markdown prompt files, creating a day-1 expectation gap. The `.claude-plugin/plugin.json` and `plugins/manifest.json` both advertise wrong skill/command/template counts. Three prior council reports flagged these same issues but 60%+ remain unfixed. **Estimated newcomer quit rate: ~60% within first 20 minutes.**

## Detailed Step-by-Step Execution Log

### Step 1 — Clone (00:00–00:30)
```bash
git clone https://github.com/roronoazoroshao369/vibe-coding-os ~/vibe-coding-os
cd ~/vibe-coding-os
```
**Outcome:** ✅ Works. No git submodule issues. No LFS files. Repo size ~50 MB (mostly markdown + JSON + a few `.mjs` scripts).

**Time cost:** <30 seconds for a clean clone.

### Step 2 — README First Read (00:30–03:00)
A newcomer reads the top of README.md. They see:
- Line 16: "**Current release (v2.17.0):** … **115 skills** · **116 commands** · **107 templates**"
- Line 18: "**Latest:** v2.17.0 — Expert Council Trim — **152→115 skills** (−24%), 120→116 commands, 110→107 templates"
- Line 270: "**128 skills**, **96 commands**, **93 templates**, **20 tracked inspiration sources**, **8 adapters**"

**Friction moment:** Three sets of stats on the same page. A newcomer assumes the top is the canonical number (115/116/107) but the "What's included" section says 128/96/93 — and neither matches the actual `node scripts/vibe-cli.mjs stats` output of **111 skills, 116 commands, 124 templates**.

**Time cost:** 2 minutes of confusion + re-reading.

### Step 3 — INSTALL.md Decision (03:00–05:00)
Three paths are presented: Plugin (Path A), Core only (Path B), Optional runtime (Path C). A newcomer on a fresh Claude Code setup will pick Path A (one-liner installer). A newcomer on Codex/Cursor picks Path B.

**Outcome:** ✅ Well-structured. Prerequisites clearly listed (Node.js 18+, git).

**Time cost:** 2 minutes.

### Step 4 — `vibe doctor` Sanity Check (05:00–06:00)
```bash
node scripts/vibe-cli.mjs doctor
```
**Observed output:**
```
Vibe Coding OS — Health Check
✓ package.json
⚠ node_modules — not found (optional)
✓ skills/  ✓ commands/  ✓ templates/  ✓ adapters/  ✓ scripts/  ✓ references/
✓ package.json is valid with validate script
Results: 8 passed, 0 failed
✅ All checks passed! Vibe Coding OS is ready.
```
**Outcome:** ✅ Works without `npm install`. The warning about `node_modules` is reasonable — validation scripts are pure Node.js + ESM, no native deps.

**Time cost:** 1 minute.

### Step 5 — `npm link` or Fallback (06:00–08:00)
**Attempted:** `npm link`
**Friction:** Fails on many Linux systems without `sudo chown -R $(whoami) /usr/local/lib/node_modules` or equivalent. The fallback path (`node scripts/vibe-cli.mjs doctor`) works but is documented as a "> Fallback" note, not a primary path.

**Outcome:** 🟡 Friction. A newcomer who fails `npm link` may think the framework is broken.

**Time cost:** 2 minutes (including Stack Overflow / docs lookup).

### Step 6 — `npm run validate:all` (08:00–12:00)
**Attempted:** `npm run validate:all`
**Friction:** Requires `npm install` first because the validation scripts import `@modelcontextprotocol/sdk` and other packages. A newcomer who runs this on a bare clone gets a module-not-found error.

**Conflict:** INSTALL.md says "core is markdown-first and works with **zero runtime and zero dependencies**" but FIRST-WORKFLOW.md immediately asks for `npm run validate:all`. The two docs contradict.

**Outcome:** 🟡 Mild friction. Fixed by `npm install`, but the dep-light promise is broken.

**Time cost:** 4 minutes.

### Step 7 — Create Target Project + `vibe init` (12:00–14:00)
```bash
mkdir ~/my-first-vibe-app && cd ~/my-first-vibe-app
echo '{"name":"test","version":"1.0.0"}' > package.json
node /tmp/vibe-coding-os/scripts/vibe-cli.mjs init claude-code
```
**Observed output:**
```
→ Initializing project with claude-code adapter (scope: recommended)...
✓ CLAUDE.md (write)
✓ .vibe/setup.json (write)
→ Global settings modified: no
→ Project-local manifest written to: /tmp/my-test-app/.vibe/setup.json
Done! Your project is ready for Claude Code.
```
**Outcome:** ✅ Works. But the generated `CLAUDE.md` contains:
- Line 14: `vibe-brainstorm, vibe-parallel-explore` — *vibe-parallel-explore* is an orphan
- Line 43: `commands/vibe-specify.md` — *vibe-specify* is deprecated

**Time cost:** 2 minutes.

### Step 8 — First `vibe spec` (14:00–18:00)
```bash
cd ~/my-first-vibe-app
node /tmp/vibe-coding-os/scripts/vibe-cli.mjs spec
```
**Outcome:** ✅ Prints a prompt to terminal. **But it does NOT generate a spec file.** The CLI is a prompt-router — the LLM assistant has to interpret the prompt and write the file.

**Friction:** A newcomer who expects `vibe spec` to auto-create `docs/specs/foo.md` will be confused. They have to:
1. Open their AI assistant (Claude Code / Codex / Cursor)
2. Paste the prompt manually
3. Have the assistant write the spec

This is the fundamental prompt-middleware gap. README doesn't explain it.

**Time cost:** 4 minutes.

### Step 9 — Next-Step Commands Fail (18:00–19:00)
```bash
node /tmp/vibe-coding-os/scripts/vibe-cli.mjs verify
# → "unknown command"
node /tmp/vibe-coding-os/scripts/vibe-cli.mjs implement
# → "unknown command"
```
**Outcome:** ❌ **Critical.** The README workflow says `verify`, `review`, `merge` are core steps, but the CLI doesn't support them as subcommands.

**Friction:** A newcomer who trusts the CLI more than the markdown will assume these features don't exist.

**Time cost:** 1 minute + frustration.

### Step 10 — Browse Examples for Real Workflow (19:00–20:00)
```bash
ls examples/react-nextjs-booking-workflow/
# → README.md  (138 lines, no code)
```
**Outcome:** 🟡 The only end-to-end example is a static README. No runnable code, no `vibe demo` command, no live walkthrough. This was flagged in the v2.16.0 audit (panel A, item #4: "no one-command end-to-end demo") and remains unfixed in v2.17.

**Time cost:** 1 minute (then the newcomer either gives up or starts manually pasting prompts).

## Workflow Friction Points (Ranked by Severity)

### F1 — 🔴 README and FAQ Stats Are Wrong (0-second trust loss)
**Files:** README.md:270, FAQ.md:15, FAQ.md:98, `.claude-plugin/plugin.json:4`, `plugins/manifest.json:5`  
A newcomer opens README.md and sees "128 skills, 96 commands, 93 templates" (line 270) — but the very same file says "115 skills, 116 commands, 107 templates" (line 16). FAQ.md says "148 skills." Five different numbers across four files. **This is the first thing a user sees and it immediately undermines credibility.**

### F2 — 🔴 6 of Top-10 Workflow Commands Missing from CLI
**Files:** `scripts/vibe-cli.mjs:851-909`, `commands/vibe-verify.md`, `commands/vibe-review.md`, `commands/vibe-merge.md`, `commands/vibe-tasks.md`, `commands/vibe-implement.md`  
The README workflow (`spec → plan → implement → test → review → memory → merge`) names 8 steps. The CLI supports only 3 as subcommands (`spec`, `plan`, `memory`). The remaining 5 are markdown prompt files that the user must manually paste into their AI assistant. A newcomer who types `vibe verify` or `vibe implement` gets an error. This creates an immediate "where's the real tool?" moment.

### F3 — 🔴 14+ Stale References to Deleted/Merged Skills
**Files:** 16 files documented in the Stale References table above  
Skills deleted in v2.17 are still mentioned in active docs, commands, and templates. While some files use "(removed in v2.17 trim)" annotations, many do not — and even the annotated ones still confuse a newcomer who crosses a term, searches for it, and finds nothing.

### F4 — 🟡 `npm link` Dependency in First-Workflow Step 1
**File:** `FIRST-WORKFLOW.md:22-25`  
The canonical first workflow says `npm link` as step 1. On many systems, `npm link` fails without `sudo` or `sudo chown`. The fallback (`node scripts/vibe-cli.mjs`) is documented in a "> Fallback" note (line 27), but a newcomer reading the numbered steps will hit the `npm link` wall first. **Recommendation:** swap the order — show the `node scripts/...` form first, then `npm link` as the optional convenience.

### F5 — 🟡 Generated CLAUDE.md References Deprecated/Old Commands
**File:** `/tmp/my-test-app/CLAUDE.md` (generated by `vibe init`)  
The auto-generated CLAUDE.md from `vibe init claude-code` contains `vibe-specify` (deprecated, line 43) and `vibe-parallel-explore` (orphan, line 14). A newcomer who follows these references will find deprecated/stale instructions.

### F6 — 🟡 No Interactive End-to-End Demo
**File:** `examples/react-nextjs-booking-workflow/README.md`  
The only end-to-end example is a 138-line static README. There is no `vibe demo` command that takes a one-line ask and runs the full spec→plan→implement→verify loop. This was flagged in the v2.16.0 audit and remains unfixed. A newcomer has no way to see the framework "in action" within the first 10 minutes.

### F7 — 🟡 `commands/manifest.json` Has Wrong Count and Stale Entries
**File:** `commands/manifest.json:5,41,106`  
`manifest.json` claims `count: 115` but the array has 115 named entries + `README.md` = 116 real commands (matching CLI `stats`). It still lists `vibe-grill-with-docs` (orphan, not in CLI help) and `vibe-specify` (deprecated). The `new_in_v2_11_0` section at line 123 lists 4 commands that were new in v2.11.0 but is not updated for v2.17.

### F8 — 🟠 No `vibe-install` Command for Skill Packs
**File:** `docs/skill-packs/core-solo-developer.md` references skills, but the only way to "install" them is via `vibe-setup-skills` (a markdown prompt) or `npm run runtime:install` (runtime-only). No CLI command copies a skill pack into your project.

## Recommendations for Next Patch

### R1 — Audit and Sync All Stats (Priority: Critical, ~15 min)
Fix the conflicting numbers across `README.md:270`, `FAQ.md:15,98`, `.claude-plugin/plugin.json:4`, and `plugins/manifest.json:5`. Set a single source of truth: **111 skills, 116 commands, 124 templates, 22 sources, 9 adapters** (or whatever `node scripts/vibe-cli.mjs stats` reports). Consider auto-generating these numbers at release time via a script.

Add `case 'verify'`, `case 'review'`, `case 'merge'`, `case 'tasks'` to `scripts/vibe-cli.mjs` that print the same prompt the .md files contain. Without this, the workflow loop is broken for CLI-first newcomers. Bonus: add `case 'implement'` too.

Update the 16 files in the Stale References table. Specifically:
- Replace *what-before-how* → *spec-first-development* (or remove the term if it's just a concept)
- Replace *zoom-out-system-context* → *brainstorming* (or remove)

- Replace *install-skill.mjs* references → *vibe-setup-skills* or remove
- Replace *vibe-grill-with-docs* → *vibe-grill-me* (Phase 2 docs-aware)

- Clean `templates/agent-alignment-template.md:42` comment
- Clean `templates/spec-template.md:70` comment
- Remove *writing-skills* refs from `docs/vi/skills-and-commands.md`

### R4 — Fix `manifest.json` and REGENERATE Plugin JSON (Priority: Important, ~15 min)
- Remove `vibe-grill-with-docs` and `vibe-specify` from `commands/manifest.json.commands[]`
- Fix `count` to 116, or better: auto-calculate from filesystem glob
- Regenerate `.claude-plugin/plugin.json` with correct counts (111 skills, 116 commands, 124 templates)

### R5 — Fix Auto-Generated CLAUDE.md Template (Priority: Medium, ~10 min)
Update the template/script that `vibe init` uses to generate `CLAUDE.md` so it:

- Removes `vibe-parallel-explore` from the Superpowers table (or keeps it but with a valid link)
