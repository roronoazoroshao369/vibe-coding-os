## 1. What v2.16.0 Actually Solves (Consensus)

### 1.1 Security (Panel B + C agree: strongest layer)
- **Defense-in-Depth (ADR-0003)**: 30-pattern injection counters + unicode normalization + base64 decoder. **Coverage: 9 ✅ / 7 🟡 / 0 ❌ across 18 OWASP failure modes.**
- **Trust Scoring (ADR-0004, NEW)**: Source-class gating (`trusted`/`read-only`/`isolated`) + bypass-loop detection — addresses the meta-attack of an attacker iterating to find a working payload.
- **30-pattern redactor** × 3 modes (postTool/postSession/postPublish), CI-gated 100% coverage at 0% FP (`tests/security/baseline.json`).
- **RTL 100% coverage** (was 97.37%) — closes U+202E bidi gap.

### 1.2 Spec → Plan → Verify Loop (Panel A: real, end-to-end)
- `commands/vibe-{init,spec,plan,implement,tdd,review,finish-branch}.md` all have substantive content (not stubs).
- `skills/core/spec-first-development`, `test-driven-development`, `adversarial-code-review`, `checkpoint-validation` close the discipline loop.
- Works in **markdown alone** — runtime optional per `docs/workflows/core-vs-optional-runtime.md`.

### 1.3 Context Discipline (Panel A: real)
- `code-context-pack`, `context-rich-implementation`, `context-policy` — forces inspection of "nearby implementations, tests, conventions" before edit. Direct counter to "agent invents from training data."

### 1.4 Discoverability (Panel A: real, but just added)
- NEW: `vibe-skill-search` (FTS5/regex across skills), `vibe-deps-graph` (visualize skill deps). Addresses 152-skill navigation complaint.

### 1.5 Quality Elevation (Panel A: real, but separate layer)
- `Quality Shield`: contract → context pack → smallest safe diff → self-review → scorecard. Real, but lives in its own layer above default loop.

### 1.6 Validation Pipeline (Panel C: 38 gates, but shallow)
- 38 gates across 7 categories, **runs in 15.5s** (parallelized). Catches obvious drift.

## 2. Pain Points Still Unsolved (3-Panel Synthesis)

### 🔴 CRITICAL (All 3 panels flagged)

1. **No template-to-command auto-binding** (Panel A). `/vibe-spec` doesn't auto-load `templates/spec-template.md`. User must remember to open template manually. **Result:** specs are freeform, inconsistent, un-reviewable.

2. **Skill discovery still requires a tool users don't know about** (Panel A). 152 skills grouped into 8 lifecycle stages, but no decision-tree tool, no "I want to add OAuth" → "use these 4 skills" guidance. `vibe-skill-search` exists but in-doc cross-links to it are sparse.

3. **No runtime RAG/context sanitization** (Panel B Gap #1). `runtime/memory/vector-store.mjs` ingests without `detectInjection()`. A poisoned upstream skill or lesson could plant indirect-injection vectors that bypass `validate-injection.mjs` (which scans files at rest, not text at retrieval time). **Biggest real-world LLM01 attack surface.**

4. **Trust scorer test is shape-only** (Panel C Gap). `tests/security/trust-scorer.test.mjs` calls `scoreSource()` and asserts only return shape `{ trust_class, risk_score }`. A broken scorer returning `{ trust_class: 'trusted', risk_score: 0 }` would pass.

5. **No redactor behavioral tests for the 3 modes** (Panel C Gap). `validate-redact.mjs` tests pattern coverage, but no test verifies `block` vs `redact` vs `log` modes produce different outputs for the same input.

### 🟠 MEDIUM

6. **No supply-chain SCA gate** (Panel B Gap). `validate-licenses.mjs` covers license headers but not CVE/vulnerability scanning (npm audit, osv-scanner). Malicious transitive dep = LLM03 + A06 blind spot.

7. **Default-deny hook is single-tool-match** (Panel B Gap). `post-tool-use-secret-scan.mjs` only fires on `Edit|Write|MultiEdit`. A secret can leak through `Bash` (`cat .env`), `WebFetch`, or `NotebookEdit`.

8. **Quality Shield bypassable in default loop** (Panel A). `README.md:114-126` 8-step loop skips "Contract" and "Scorecard" entirely. Opt-in, not opt-out. New users miss the strongest defense.

9. **Coverage and trust are in tension** (Panel A). Framework itself ships at ~4.5% direct test coverage (17 of 374 artifacts). Asking users to trust quality discipline when the framework is undertested = credibility gap.

10. **`vibe init` flags not documented in QUICKSTART** (Panel A). `vibe init claude-code` / `cursor` / `codex` / `gemini` shown, but `--tool`, `--scope`, `--current-terminal`, `--project`, `--dry-run` flag semantics are missing.

11. **No "from one-line ask to verified PR" end-to-end demo** (Panel A). `examples/react-nextjs-booking-workflow/` is static. First 30 minutes are highest-friction moment.

12. **Cursor / Gemini / Codex paths are second-class** (Panel A). Claude Code plugin is recommended; others are "manually paste CLAUDE.md into rules."

13. **Property test FP noise** (Panel C). 68/382 failures are systematic: 52 from HTML-tag heuristic, 16 from intentional template placeholders. Inflates noise.

14. **Quality engine text-vs-exit-code mismatch** (Panel C). `--profile=lean` prints "Result: FAIL" for skipped advisory gates yet exits 0. UX hazard.

15. **No semantic jailbreak detection** (Panel B). Lexical regexes catch `DAN`, "you are now", "ignore previous" — but paraphrase, non-English role-play, compressed payloads (base64 of "ignore…", Cyrillic "ignоre") bypass.

### 🟢 NICE-TO-HAVE

16. No spec/plan diff command (Panel A).
17. No memory file convention surfaced in workflow (Panel A).
18. No plugin install verification step (Panel A).
19. No concurrent-execution gate (Panel C).
20. No performance budget gate (Panel C).
21. No license compatibility check with `node_modules` (Panel C).
22. Fuzz testing is structural-only (Panel C).
23. Cross-turn state poisoning not gated (Panel B).
24. Unbounded consumption (LLM10) not gated (Panel B).
25. System-prompt integrity signing/hashing recommended, not implemented (Panel B).

## 3. Top 10 Recommendations for v2.17.0 (Ranked by Impact × Confidence)

### Tier 1 — High Impact, High Confidence (DO FIRST)

1. **RAG-ingest sanitizer** (Panel B P1). Add `scripts/validate-rag-ingest.mjs` calling `detectInjection()` on every document entering `runtime/memory/vector-store.mjs` and `lessons-learned-db`. Refuse ingest on `severity=error`. **Closes biggest real-world LLM01 surface.**

2. **Auto-bind templates to commands** (Panel A P2). Make `vibe-spec` auto-inject `templates/spec-template.md`, `vibe-plan` inject `templates/plan-template.md`, `vibe-tdd` inject a minimal red-green checklist. One-line `--dry-run` preview.

3. **Behavioral tests for trust scorer + redactor** (Panel C P1). Test that known-malicious patterns receive lower trust scores than benign content. Test that 3 redactor modes produce different outputs for same input. **Closes two high-severity test gaps.**

4. **SCA gate** (Panel B P4). Add `npm audit --omit=dev` or `osv-scanner --lockfile=package-lock.json` to `validate:all`. Fail build on `severity=high`. **Closes LLM03 + A06.**

5. **Default-on Quality Shield for non-trivial work** (Panel A P3). Change `README.md:114-126` so the 8-step loop inserts Contract → Context pack → Smallest safe diff → Self-review → Scorecard as **required** for any change spanning >1 file or touching behavior.

### Tier 2 — High Impact, Medium Confidence

6. **`vibe doctor --goal "X"` skill-chain recommender** (Panel A P4). Reads goal, queries `registry/skills.json` + `commands/manifest.json`, prints exact skill/command/template chain with clickable paths.

7. **Broaden secret-scan hook** (Panel B P5). Add `Bash`, `WebFetch`, `NotebookEdit` matchers. Or move secret scan to `UserPromptSubmit` + `SessionEnd`.

8. **End-to-end demo command** (Panel A P1). `vibe demo invoicer-csv` (or similar) that takes a one-line goal, runs spec → plan → implement → review → verify on a known starter repo, shows every output. Closes day-1 activation gap.

9. **Fix property test FP noise** (Panel C P2.1-2). Allowlist safe HTML tags (`<details>`, `<summary>`, `<table>`). Exempt `*template*` files from `no_placeholder_content`. Drops 68/382 failures to ~10.

10. **Wire real parsers into fuzz harness** (Panel C P4.2). `property-test-runner.mjs` line 584 aspiration: "Future: pass generated inputs through actual skill/command/template parsers" → ship it.

### Tier 3 — Medium Impact, Higher Effort

11. Semantic/embedding-based detector behind feature flag (Panel B P6).
12. Output schema validation module `validate-output-schema.mjs` (Panel B P7).
13. Performance budget gate (validate:all ≤ 30s) (Panel C P3).
14. License compatibility with `node_modules` (Panel C P3).
15. Vietnamese CLI output for all error messages (Panel A friction).

## 5. Final Verdict

**v2.16.0 = "Strong bones, thin seams."**

- **The bones are real.** Every command and skill I opened has substantive content. The spec → plan → verify loop is end-to-end and works in markdown alone. Security wiring (Trust Scoring, RTL 100%, redactor) is the most material improvement and is genuinely differentiated.
- **The seams are weak.** Template-to-command binding is missing. The default loop bypasses the strongest layers (Quality Shield, adversarial review). Skill discovery requires a search tool the user doesn't know about. The framework itself ships at ~4.5% test coverage. And for non-Claude-Code users (Cursor, Gemini), the path is still "manually paste CLAUDE.md into rules."
- **The ceiling is high** (the framework *can* solve the hard problems). **The floor — what a developer experiences in their first hour — has not been raised as much as the marketing implies.**

**Recommended next sprint (v2.17.0):** Tier 1 above. 5 items, 1 sprint. RAG sanitizer + template auto-bind + behavioral tests for security + SCA gate + default-on Quality Shield. That single sprint would close 5 of 6 CRITICAL gaps.
