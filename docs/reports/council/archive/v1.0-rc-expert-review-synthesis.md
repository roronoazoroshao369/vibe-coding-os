## 4. ❌ Security / Safety Reviewer — The Blocker

**Verdict: NO-GO nếu tiêu chuẩn RC bao gồm security assurance thực chất.**

### Critical Findings

#### 4a. Secret scan only scans staged diff, not full repo
Script uses `git diff --cached` — passes even if secrets exist committed in history or in unstaged files.

**Impact:** "0 secrets found" claim is misleading. Need either on-disk scan with safe allowlist or integration with gitleaks/trufflehog.

#### 4b. Secret pattern coverage insufficient
Missing patterns for:
- Stripe: `sk_live_*`, `sk_test_*`, `whsec_*`
- Slack: `hooks.slack.com/services/...`
- npm: `npm_*`
- Database URLs with embedded credentials
- Azure/GCP service accounts
- GitLab/Heroku/Twilio/SendGrid tokens

**Impact:** Could have secrets but gate wouldn't catch them.

#### 4c. Memory redaction tests don't test the real redactor
`verify-memory-redaction.mjs` defaults to a built-in sample redactor, not `runtime/core/privacy.mjs`. The export names don't even match (`redactText`/`redactObject` vs expected `redact`).

**Impact:** Memory redaction "PASS" doesn't prove runtime redaction works.

#### 4d. Test fixtures use abstract placeholders, not realistic shapes
Tests like `"API key is STRIPE_SECRET_KEY_PLACEHOLDER"` with fail pattern `sk_live_` — the input never contains `sk_live_`, so redactor could be broken for Stripe keys and tests still pass.

#### 4e. Injection scan has blind spots
Doesn't scan `adapters/`, `registry/`, `runtime/` (most of it), `scripts/`. File-level allowlist for one doc is too broad.

#### 4f. License/attribution risk
`eyaltoledano/claude-task-master` (MIT + Commons Clause) has local targets `runtime/tasks/task-store.mjs` and `scripts/runtime-task.mjs` in mapping docs, but `ATTRIBUTIONS.md`/`NOTICE.md` claim no runtime adoption. Needs audit before RC.
