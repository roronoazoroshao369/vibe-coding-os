## Blockers (must fix before v1.4)

### B1: `react-nextjs` pack has NO React/Next.js-specific skills
**Severity: HIGH** | Architect

The pack description promises "React/Next.js specific skill pack" but all 13 skills are generic engineering disciplines (anti-overengineering, clean-code, TDD, etc.). No React component patterns, no hooks, no Next.js routing, no server components. Users expecting frontend-specific guidance will be disappointed.

**Fix options:**
- Option A: Rename to `frontend-discipline` (reflects actual content)
- Option B: Add React/Next.js-specific skills and make the pack match its description

### B2: 3 of 4 packs reference `vibe-test` command that doesn't exist
**Severity: MEDIUM** | Architect

All non-memory packs previously listed `vibe-test` as a suggested command, but no matching command file existed. This was fixed in Sprint 3.1 by removing `vibe-test` from all pack manifests.

### B3: No overwrite protection
**Severity: MEDIUM** | CLI

`vibe install-pack core-solo` silently overwrites all skill files, pack-manifest.json, and README.md if `.vibe/skills/core-solo/` already exists. Unlike `vibe export` (which warns about existing files), `install-pack` gives no warning.

**Fix:** Add a `--force` flag. Without it, warn before overwriting.

## Warnings (should fix)

### W1: Pack/skill names not validated
**Severity: MEDIUM** | CLI

`packName`, `pack.name`, and `skill.name` are used in file paths without slug validation. Current packs are safe, but if users or future packs modify names, path traversal becomes possible.

**Fix:** Validate against `/^[a-z0-9][a-z0-9-]*$/` before using in paths.

### W2: README has competing pack entry points
**Severity: LOW** | Docs

README contains both `docs/skill-packs/` (older curated packs section) and the new `docs/SKILL-PACKS.md` link. Users see two different pack entry points.

**Fix:** Update the old `docs/skill-packs/` reference to point to `docs/SKILL-PACKS.md` or clarify the distinction.

### W3: CONTRIBUTING-SKILLS.md not linked from entry points
**Severity: LOW** | Docs

The contributor guide exists but is not discoverable from README or CONTRIBUTING.md. Contributors will not find it.

**Fix:** Add link from README.md "New documentation" section and/or CONTRIBUTING.md.

### W4: Tests only assert exit codes
**Severity: LOW** | CLI

The install-pack smoke tests verify exit status but do not check that:
- `.vibe/skills/<pack>/` directory was created
- Expected `.md` files exist
- `pack-manifest.json` has valid content
- `README.md` was generated

**Fix:** Add content assertions after real install test.

### W5: Unknown CLI flags silently ignored
**Severity: LOW** | CLI

`vibe install-pack core-solo --bad-flag` exits 0 with no warning. Users may think the flag was accepted.

**Fix:** Reject or warn on unknown flags.

### W6: Unused variable in `--dry-run-first` branch
**Severity: LOW** | CLI

In `cmdInstallPack`, the `--dry-run`-first branch computes `const packs` but does not use it (it's declared in both the if-block and the error branch).

**Fix:** Remove unused declaration.

## Suggestions (nice to have)

### S1: Add pack composition/extends mechanism
Architect flagged that common baseline skills (vibe-bootstrap, writing-plans, systematic-debugging) are repeated across 3-4 packs. As packs grow, updates require editing many manifests. Consider a `base` or `extends` field in pack.json.

### S2: Add `vibe list-packs` command
Currently the only way to see available packs is `vibe install-pack` with no args (which errors and prints them). A proper `list-packs` command would be cleaner UX.

### S3: Add "After install" section to docs
SKILL-PACKS.md doesn't explain what to do after installation. Users don't know how to make their AI assistant discover the installed skills under `.vibe/skills/`.

### S4: Pack skill list visibility
SKILL-PACKS.md doesn't list which skills each pack contains. Users can't see the exact content without reading pack.json.

### S5: Pack manifest schema validation
Add a JSON schema for `pack.json` and a validation gate in `validate:all` to catch missing fields, unknown fields, and broken skill references.

### S6: `memory-safe` pack under-composed
Memory pack omits related skills like agent-handoff, session-summarizer, context-retrieval. May be intentional for size, but the description promises "repeatable context handoffs."

### S7: Vietnamese section in English CONTRIBUTING doc
"Link related skills in the 'Ghi chú tiếng Việt' section" is oddly specific for an English doc. Should be rephrased as generic guidance.
