# Vibe Coding OS v1.0.0 — Final Release Notes

> **Status:** Final release — stable v1.0 Trusted Workflow Framework.
> **Tag:** `v1.0.0`
> **Release date:** 2026-06-17

---

## Summary

Vibe Coding OS v1.0.0 is the first stable release of the **Trusted Workflow Framework**: a markdown-first AI coding operating system for disciplined, reviewable, and validation-backed software work.

This release finalizes the stable core workflow contract, registry schemas, validation gate, adapter support tiers, governance process, release automation, and documentation needed to treat the project as a dependable v1.0 baseline.

---

## Highlights

- **Stable core workflow contract** — Intent → Spec → Plan → Implement → Test → Review → Memory → Merge.
- **13-gate validation baseline** — repo, references, traceability, injection, secrets, schemas, memory redaction, adapter smoke tests, CLI smoke tests, E2E workflow, dashboard data, dashboard sync, and evaluation report.
- **Stable registry schemas** — contracts for skills, commands, templates, and reference intelligence.
- **Adapter support tiers** — Tier 1 Full support for Claude Code and Codex CLI; Tier 2 Community support for Cursor and Gemini CLI.
- **Release-ready governance** — contribution governance, ADR process, maintainer guide, release checklist, support matrix, compatibility policy, and issue/PR templates.
- **Final v1.0 release metadata** — package version, changelog, dashboard, roadmap status, and release notes aligned to `v1.0.0`.

## What Changed Since v0.4.0

All changes since v0.4.0 focus on hardening, validation, governance, compatibility, and release readiness for the stable v1.0 line.

### Added

- **Dashboard sync validation** (`scripts/check-dashboard-sync.mjs`, `npm run dashboard:check`) — verifies `docs/DASHBOARD.md` matches live package version, inventory counts, narrative file count, and orphan counts; included in `npm run validate:all`.
- **Issue and PR templates** — release checklist, compatibility report, safety/eval report issue templates; PR template includes v1.0 gate checks.
- **v1.0 governance docs** — `docs/governance.md`, `docs/decision-record-process.md`, and `docs/maintainer-guide.md`.
- **v1.0 release plan** (`docs/v1.0-release-plan.md`) — scope, done criteria, release gates, RC strategy, and release manager workflow.
- **v1.0 RC checklist** (`docs/v1.0-rc-checklist.md`) — RC validation, documentation completeness, and post-merge verification steps.
- **Support matrix** (`docs/support-matrix.md`) — adapter support tiers and compatibility summary.
- **Stable registry schemas** (`schemas/`) — reference index, skill, command, and template contracts validated by `npm run validate:schemas`.
- **CLI smoke tests** (`scripts/smoke-test-cli.mjs`, `npm run smoke-test:cli`) — read-only CLI command coverage.
- **Dashboard generator** (`scripts/generate-dashboard.mjs`, `npm run dashboard:generate`) — regenerates `docs/DASHBOARD.md` from live repo data.
- **End-to-end CLI workflow test** (`scripts/test-e2e-workflow.mjs`, `npm run test:e2e`) — template copy workflow, CLI command assertions, and cleanup.
- **Release dry-run automation** (`scripts/release.mjs`, `npm run release:dry-run`) — validates readiness and prints exact tag/release next steps without pushing tags.
- **CI full validation** — `.github/workflows/validate.yml` runs the complete `npm run validate:all` gate.
- **Readiness and audit reports** — `docs/reports/v1.0-readiness-report.md` and `docs/reports/v1.0-final-audit.md`.

## Stable in v1.0

The following interfaces and policies are considered stable for the v1.0 release series:

- **Core workflow contract:** Intent → Spec → Plan → Implement → Test → Review → Memory → Merge.
- **Adaptive task tiers:** Tiny, Small, Medium, Large, and Risky.
- **Registry schemas:** skills, commands, templates, and reference index.
- **Validation gate:** 13 automated checks required before v1.0+ release publication.
- **Adapter support tiers:** Tier 1 Full for Claude Code and Codex CLI; Tier 2 Community for Cursor and Gemini CLI.
- **Compatibility policy:** SemVer-based compatibility expectations, breaking-change definitions, deprecation process, and release gate requirements.
- **Skill packs:** Core Solo Developer, Memory-Safe, Multi-Agent, and Upstream Intelligence.
- **CLI helper baseline:** `vibe init`, `vibe doctor`, `vibe stats`, `vibe list-skills`, and `vibe list-commands`.
- **Documentation baseline:** English and Vietnamese README/onboarding surfaces, quickstart guides, tutorials, release packaging, roadmap status, and dashboard.

## Upgrade Notes

Upgrading from v0.4.0 to v1.0.0 does **not** require workflow changes for most users. The core markdown-first usage model is unchanged.

1. Fetch and check out the final release tag after publication:
   ```bash
   git fetch origin
   git checkout v1.0.0
   ```

2. Re-run the full validation gate:
   ```bash
   npm run validate:all
   ```

3. Review adapter setup and support tiers:
   - `docs/QUICKSTART.md`
   - `docs/support-matrix.md`
   - `docs/compatibility-support-policy.md`

4. Optional runtime users should re-run the runtime installer from the repository root if they use runtime-local state or MCP tools.

---

## Known Limitations

- Optional runtime features in `runtime/` remain opt-in and may evolve independently from the stable core workflow framework.
- Tool-specific behavior is guaranteed only to the extent documented in the support matrix and compatibility policy.
- Vietnamese documentation is maintained for onboarding and major user-facing surfaces; some deep governance/release docs may remain English-first.

---

## Final Release Steps

After release signoff and merge to the target release branch:

```bash
node scripts/release.mjs --tag --version 1.0.0
git show v1.0.0
git push origin v1.0.0
gh release create v1.0.0 --title "v1.0.0" --notes-file docs/releases/v1.0.0.md
```

Do not create or push the final tag from an unmerged PR branch.
