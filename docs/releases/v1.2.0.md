# Vibe Coding OS v1.2.0 Release Notes

**Date:** 2026-06-17
**Status:** Released
**Primary change PR:** [PR #39](https://github.com/roronoazoroshao369/vibe-coding-os/pull/39)

---

## What's New

Vibe Coding OS v1.2.0 advances the optional runtime from a permissive local state layer toward enforceable multi-agent contracts with strict schemas, richer provenance, safety review records, and migration support.

Highlights:

- **Docs drift hotfix:** release-facing counts, version progress, orphan wording, Vietnamese strategy wording, and validator coverage were corrected to keep project status trustworthy.
- **Runtime schema v2 foundation:** runtime collections and items now have a clearer envelope for authorship, source, traceability, risk, metadata, and extension points.
- **Multi-agent state contracts v2:** task, workflow-run, checkpoint, session, team, and memory schemas now describe handoff-ready coordination fields.
- **Safety + traceability:** action/event/approval/tool-contract schemas make risky execution, rollback expectations, artifacts, and provenance easier to inspect.
- **Migration readiness:** a migration manifest and dry-run engine establish a safer path for upgrading runtime state.

---

## Breaking Changes

None intended. The v2 contracts preserve backward-compatible validation paths where possible while introducing stricter schema definitions for new runtime state.

---

## Migration

No manual migration is required for markdown-first core users.

Optional runtime users should treat v1.2 migration tooling as the preferred upgrade path for persisted runtime state:

```bash
npm run validate:all
# use runtime migration dry-run before applying runtime-state upgrades
```

## Full Changelog

### P0 — Docs Drift Hotfix

- Fixed dashboard validation gate count and version progress drift.
- Updated README template counts and orphan wording so release-facing inventory matches the generated repository state.
- Rewrote/refreshed Vietnamese strategy wording to avoid stale roadmap claims.
- Expanded validators to catch repeated stale counts and dashboard/version drift earlier.

### P1A — Runtime Schema v2 Foundation

- Added runtime envelope fields such as `contractVersion`, `runtimeId`, and `revision`.
- Added common item envelope concepts for `createdBy`, `source`, `trace`, and `risk`.
- Tightened runtime schemas with `additionalProperties: false` on item contracts where applicable.
- Preserved explicit `metadata` / `extensions` placeholders as supported escape hatches.
- Maintained backward-compatible validation for legacy fields while enabling stricter v2 state.

### P1B — Multi-Agent State Contracts v2

- Expanded task contracts with claim/lease fields, priority, phase, history, verification, handoff, risk, and acceptance criteria.
- Expanded workflow-run contracts with intent, refs, gates, artifacts, and resume metadata.
- Expanded checkpoint contracts with subject type/id, evidence, decision, limitations, and resume hints.
- Expanded session contracts with status, participants, refs, decisions, open questions, and handoff metadata.
- Expanded team contracts with orchestration policy, role capabilities, review gates, contracts, and safety policy references.
- Expanded memory contracts with kind, freshness, provenance, privacy, retrieval, and scope fields.

### P1C — Safety + Traceability

- Added action v2 coverage for type, actor, tool/tool_v2, result, risk, trace, and artifacts.
- Added runtime event schema for normalized timestamped provenance records.
- Added approval schema with subject, risk level, approval status, rationale, and rollback fields.
- Added runtime tool-contract schema for adapter/tool capability declarations.

### P1D — Migration Manifest + Dry-Run Engine

- Added runtime migration manifest schema.
- Added dry-run migration support to inspect upgrade impact before applying changes.
- Established safer runtime-state upgrade expectations around backups, idempotency, and rollback-aware manifests.
