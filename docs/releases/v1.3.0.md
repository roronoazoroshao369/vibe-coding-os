# Vibe Coding OS v1.3.0 Release Notes

**Date:** 2026-06-17
**Status:** Released
**Primary change PR:** TBD

---

## Overview

Vibe Coding OS v1.3.0 is a major optional-runtime production-readiness release. It moves runtime state from documented contracts toward enforced write-time guarantees, adds multi-agent claim/lease ownership APIs, strengthens safety and recovery operations, and introduces behavioral integration coverage for the runtime surface.

Highlights:

- **Trust cleanup:** release-facing docs, roadmap history, release notes, and heading-version validation were tightened so public status matches repository state.
- **Runtime enforcement core:** all runtime stores now validate item shape, collection strictness, known fields, risk bounds, and action records before writes.
- **Claim/lease task APIs:** multi-agent task ownership now has explicit claim, release, heartbeat, renewal, expired-claim listing, and cancellation flows.
- **Safety & recovery:** dangerous actions can be routed through approval gates, tool boundaries fail closed by default, and runtime audit/replay/snapshot/migration commands improve recovery posture.
- **Behavioral integration tests:** runtime behavior is covered by 9 test files and 76 test cases, with gate #18 included in `validate:all`.

## Migration Notes

No manual migration is required for markdown-first core users. Skills, commands, templates, docs, and adapters remain usable as plain repository artifacts without enabling the optional runtime.

Optional runtime users should review persisted local runtime state before adopting v1.3.0 in active multi-agent workflows:

1. Run the full validation gate before and after upgrade:

   ```bash
   npm run validate:all
   ```

2. Use runtime audit tooling to inspect local state and safety posture:

   ```bash
   vibe runtime-audit
   ```

3. Use migration status/backup/apply/rollback workflows for persisted runtime state instead of editing store files directly.

4. If multiple agents may work on the same task store, use the new claim/lease APIs instead of ad hoc ownership fields:

   ```bash
   vibe runtime-task claim <task-id>
   vibe runtime-task heartbeat <task-id>
   vibe runtime-task release <task-id>
   ```

5. Treat tool boundary enforcement as fail-closed by default. Explicitly define allowed tool contracts before relying on automated or high-risk runtime actions.

Breaking changes are not intended for markdown-first users. Runtime users may see previously accepted malformed or over-broad runtime items rejected at write time because enforcement now applies before store writes.
