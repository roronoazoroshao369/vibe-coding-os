# Vibe Coding OS v0.4.0 — Release Notes Draft

> Draft for the GitHub Release page. Do not tag from this PR branch; publish after merge.

## Summary

v0.4.0 packages the current Vibe Coding OS kernel into a more adoption-ready, evidence-backed release. It keeps the core markdown-first and dependency-light while improving onboarding, validation, safety checks, release packaging, skill packs, and v1.0 foundation docs.

## Highlights

### Adoption MVP

- 10-minute quickstart and adapter install snippets for Claude Code, Codex CLI, Cursor, Gemini CLI, and other assistants.
- CLI workflow examples and read-only helper commands for common discovery and setup tasks.
- Project dashboard with live inventory counts and release health signals.

### Evidence & Safety

- Full validation posture documented around repository structure, references, traceability, prompt-injection signatures, secrets, memory redaction, adapter smoke tests, and evaluation reporting.
- Validation status for this release target: **11/11 gates passing**, **0 broken refs**, **0 orphans**, **0 secrets**.
- Memory redaction checks and safety-oriented workflow docs make verification evidence easier to review before merge/release.

### Packaging / Skill Packs

- Release packaging guide and checklist for versioning, release notes, GitHub release creation, and post-merge tagging.
- Curated skill packs for Core Solo Developer, Memory-Safe, Multi-Agent, and Upstream Intelligence workflows.
- README status refresh points users to the dashboard, quickstart, roadmap status, and release-packaging docs.

### v1.0 foundation

- Core workflow contract, compatibility/support policy, governance, decision-record process, maintainer guide, registry schemas, and validation coverage prepare the project for a future v1.0 release candidate.
- `ROADMAP-STATUS.md` tracks v1.0 hardening progress and remaining release-candidate work.

## Upgrade / usage notes

- Core usage remains markdown-first: install/use the Claude Code plugin or copy `CLAUDE.md` / `AGENTS.md`, then invoke `/vibe-*` commands and attach relevant skills/templates.
- The runtime remains fully opt-in. Existing markdown-only users do not need to run the daemon, MCP server, tmux runner, or vector-memory components.
- For setup, start with `docs/QUICKSTART.md`; for health and inventory, see `docs/DASHBOARD.md`; for release operations, see `docs/RELEASE-PACKAGING.md`.
- If you use CI badges or release links, merge this PR before creating the release tag so URLs resolve against the default branch.

## Post-merge tag instruction

After this release PR is merged into the target branch, create and push the release tag from the merged commit only:

```bash
git checkout main
git pull --ff-only
git tag v0.4.0
git push origin v0.4.0
```

Then create the GitHub Release titled `v0.4.0` and paste these notes, adjusting validation output if the final post-merge run differs.
