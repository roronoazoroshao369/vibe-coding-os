# v1.5.0 — Core Adoption & Runtime Freeze

Release date: 2026-06-17

## Summary

v1.5.0 formalizes Vibe Coding OS as a **portable workflow contract + discipline layer**. The optional runtime is now scope-frozen: it remains local-first and maintainable, but new product capability must land in markdown core first.

This release also improves Vietnamese onboarding, adds a feedback loop, and hardens existing runtime boundaries without expanding runtime scope.

## Highlights

- ADR 0002: Runtime Scope Freeze.
- README.vi.md dieted from 536 lines to 194 lines.
- New Vietnamese Quickstart: `docs/vi/QUICKSTART.md`.
- ROADMAP-STATUS updated through v1.5.0.
- Support matrix and ADR 0001 now point to freeze posture.
- Config hardening: invalid risk levels and malformed tool lists reset to defaults.
- MCP approval specificity: approval subjects include argument hash.
- Negative TTL rejected in public claim/heartbeat/renew APIs.
- Adoption feedback issue template added.
- Runtime behavior aggregate reconciled as 14/14 test files PASS.

## Runtime freeze policy

Runtime changes are now limited to:

1. bug fixes;
2. security/safety hardening;
3. compatibility maintenance;
4. validation/test coverage;
5. documentation.

New runtime expansion requires a future ADR exception and must pass the Engine Adoption Gate.

## Validation

- `npm run runtime:behavior-tests`: **14/14 PASS**
- `npm run validate:all`: expected **20/20 PASS** before merge

## Upgrade notes

No breaking core workflow changes.

If you relied on negative TTL to simulate expired claims in tests, update tests to backdate `claim.expiresAt` directly through a test-only raw store write.
