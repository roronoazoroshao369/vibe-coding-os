# Vibe Coding OS v1.4.2 — Runtime Hardening & Adoption Trust Fix

**Date:** 2026-06-17
**Status:** Stable patch release

## What's New

### Bug Fixes
- **tmux mapResults() state transition:** Fixed `pending → completed` violation. Now correctly transitions `pending → in_progress → completed`.
- **maxTaskLease enforcement:** `heartbeatTask()`, `renewTaskLease()`, and `updateTaskStatus()` now all enforce the configured `maxTaskLease` cap (was only enforced in `claimTask()`).

### Schema & Validation
- **Event schema v2 fields:** Added `seq`, `idempotencyKey`, `correlationId`, `causationId` to `runtime-event.schema.json`.
- **Date-time format:** Runtime validator now enforces `format: "date-time"` for ISO 8601 strings.

### Shell Safety
- **tmux outFile:** Output file paths now use `shQuote()` to prevent shell injection with special characters.
- **Duplicate role names:** `prepareTeamRun()` now detects and rejects duplicate sanitized role names.

### Docs & Adoption
- **README links:** Release notes links now point to v1.4.2.
- **Bilingual prompts:** Vietnamese FIRST-WORKFLOW now includes both English and Vietnamese prompt variants for steps 6a-6d.

### Tests
- Added 4 new maxTaskLease enforcement tests across claimTask, heartbeatTask, renewTaskLease, and updateTaskStatus.
