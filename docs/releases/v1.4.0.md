# Vibe Coding OS v1.4.0 Release Notes

**Date:** 2026-06-17
**Status:** Released
**Primary change PRs:** #51, #52, #53, plus release-prep PR for v1.4.0

---

## Overview

Vibe Coding OS v1.4.0 adds an optional local runtime kernel and hardens it for correct, automatable use. The release keeps the product positioned as a **portable workflow contract + discipline layer**, while making the optional runtime more trustworthy for local task tracking, event history, and diagnostics.

Highlights:

- **Runtime kernel:** optional config layer, formal task state machine, and broader schema enforcement.
- **Event Store v2:** sequence numbers, correlation and causation IDs, idempotency keys, metadata consistency checks, and tail/latest event queries.
- **Runtime observability:** machine-readable diagnostics with `vibe doctor --json` and `vibe events --json`.
- **Contract hardening:** JSON-only output for automation surfaces, maxTaskLease enforcement, and clearer runtime boundary documentation.

---

## Changes

### Runtime Kernel

- Added `runtime/core/config.mjs` for optional runtime configuration.
- Added `runtime/core/task-state-machine.mjs` with explicit transition rules for `pending`, `in_progress`, `blocked`, `completed`, and `cancelled`.
- Broadened JSON Schema validation coverage in `runtime/core/validation.mjs`.
- Integrated the task state machine into task-store status updates.

### Event Store v2

- Added `runtime/core/event-store.mjs` as the canonical event API.
- Added event sequence numbers, correlation IDs, and causation IDs.
- Added `idempotencyKey` support for safe repeated append calls.
- Added metadata consistency checks and locked append behavior.
- Made legacy `events.mjs` append path wrap canonical v2 behavior.

### Runtime Observability

- Added `runtime/core/doctor.mjs` for health diagnostics.
- Added `vibe doctor --json`.
- Added `vibe doctor --project <path> --json`.
- Added `vibe events --json`.

### Runtime Hardening

- Fixed `vibe doctor --json` to emit JSON-only output.
- Fixed `vibe events` to show latest/recent events correctly.
- Added `--limit` validation for event CLI output.
- Added config-enforced `maxTaskLease` behavior in claim/renew APIs.
- Added runtime boundary documentation in `docs/RUNTIME.md`.

### Tests & Validation

- Added event-store v2 tests, doctor tests, and CLI JSON contract tests.
- Expanded runtime behavioral test coverage.
- Kept full validation passing at 26/26 gates.

## Migration Notes

For markdown-first users, no migration is required.

For optional runtime users:

1. Run the full validation gate:

   ```bash
   npm run validate:all
   ```

2. Use the new diagnostics surface:

   ```bash
   vibe doctor
   vibe doctor --json
   vibe doctor --project .
   vibe events --json
   ```

3. Prefer canonical event APIs and JSON automation surfaces for script/CLI integration.

4. If you relied on previous local runtime behaviors, review event metadata and local runtime state after upgrade.

This release keeps the runtime optional and local-first. It strengthens runtime correctness without repositioning Vibe Coding OS as a competing orchestration engine.
