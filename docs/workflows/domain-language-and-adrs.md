# Workflow: Domain Language and ADRs

## Purpose

Domain Language and ADRs.

## When to use

Use when terminology or decisions need durable repository memory.

## Step-by-step workflow

1. Inspect `CONTEXT.md` and ADR index.
2. Identify terms/ambiguities.
3. Update glossary concisely.
4. Draft ADR only for real decisions.
5. Link docs to PRD/issues.

## Required inputs

Conversation, code terms, decision options, constraints.

## Outputs

Context updates, ADR draft/update, linked decisions.

## Related skills

shared-domain-language, architecture-decision-records, project-memory.

## Related commands

`vibe-grill-with-docs`, `vibe-handoff`, `vibe-memory`.

## Maintenance notes

When upstream changes context/ADR guidance, update this workflow and templates.

## Ghi chú tiếng Việt

Dùng để giữ ngôn ngữ và quyết định nhất quán. Không tạo ADR giả.
