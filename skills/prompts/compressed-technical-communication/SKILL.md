# Skill: Compressed Technical Communication

## Purpose

Communicate in dense, precise technical shorthand when the user asks for brevity or context is expensive.

## When to use

Use for status updates, handoffs, or expert collaboration where concise technical signal matters more than explanation.

## Inputs

Audience expertise, topic, required precision, and any facts that must not be compressed away.

## Workflow

1. Remove filler and motivational language.
2. Keep identifiers, commands, risks, and decisions precise.
3. Use bullets or terse tables.
4. Do not compress away uncertainty, safety warnings, or validation results.
5. Expand again when the user asks or stakes are high.

## Outputs

A short high-signal answer, checklist, status report, or technical brief.

## Failure modes

Being cryptic, omitting caveats, sounding rude, or using compression for novices who need explanation.

## Verification checklist

Meaning is preserved; commands and file names are exact; uncertainty remains visible; tone is professional.
