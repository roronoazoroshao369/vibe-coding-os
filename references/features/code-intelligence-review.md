## Purpose

The Code Intelligence Review pattern adapts ideas from local-first code intelligence graphs into Vibe Coding OS's portable, markdown-first review workflow. Instead of reviewing a diff as a flat sequence of line changes, the reviewer first builds a lightweight structural map of the code region the diff touches — call graphs, dependency chains, data flow, and test coverage — and then reads the diff through that map.

## Local implementation

- `skills/core/code-intelligence-review/SKILL.md` — The skill that defines the 6-step intelligence-gathering and review workflow. Covers scoping, dependency enumeration, call graph construction, test gap mapping, diff analysis, and review production. Includes practical examples per step, a verification checklist, and an optional MCP adapter path.
- `templates/code-intelligence-review-template.md` — Structured template for recording the intelligence map with sections for scope, dependency graph, call graph, test coverage, and a Code Intelligence Summary.
- `commands/vibe-review-intelligence.md` — Command that invokes the intelligence-aware review. Supports `--incremental`, `--mcp`, and `--scope` options.
- `adapters/mcp/code-intelligence-tool-pattern.md` — Optional MCP adapter for accelerating dependency enumeration and call graph construction.

## Key design choices

1. **Scope-first.** The map is bounded to the diff's region plus immediate neighbours. Building a full codebase graph is explicitly out of scope — the overhead would defeat the purpose for most reviews. One-hop traversal is the default; deeper traversal requires flagged risk.

2. **Dependency enumeration is mandatory.** Step 2 of the skill requires enumerating direct imports, callers, callees, and data flow for each changed file. This surfaces ripple effects that a line-by-line scan would miss. Skipping this step collapses the review back to flat line-by-line reading.

3. **Test gap analysis is integrated.** The intelligence map records per-function and per-dependency-chain coverage status, prioritising gaps by risk. This connects structural understanding to testing discipline and surfaces untested error paths before they become production incidents.

4. **Practical examples ground each step.** Steps 1–4 include concrete examples drawn from a checkout pipeline scenario, showing exactly what the reviewer records and why. This makes the abstract workflow concrete for new users.

5. **MCP acceleration is optional.** The default workflow is pure markdown and reading; an MCP adapter can speed up dependency resolution for agents that support the protocol. The adapter contract documents the input/output schema for both `build-map` and `incremental-diff` MCP tools.

6. **Incremental re-analysis support.** The intelligence map serves as a baseline for subsequent incremental review rounds. The `incremental-review` skill reuses the map to compute only what changed, making repeated reviews of the same area token-efficient.

## Relationship to existing review skills

The Code Intelligence Review sits alongside `requesting-code-review`, `receiving-code-review`, and `review-before-merge` as an optional enhancement. The intelligence map can be requested by the author (`--intelligence` option in `vibe-request-review`), generated by the reviewer before analysis, or used incrementally across multiple review cycles via the `incremental-review` skill.
