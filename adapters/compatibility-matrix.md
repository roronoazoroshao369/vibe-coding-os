# Adapter Compatibility Matrix

Use this matrix to choose the lightest setup for each assistant environment. The framework artifacts stay portable: commands are reusable prompts, skills are operating procedures, templates are project files, and memory should remain explicit and safe.

| Tool | Primary instruction file | Commands support | Skills support | Templates support | Memory workflow | Multi-agent workflow | Validation command | Known limitations | Recommended setup |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Claude Code | `CLAUDE.md` | Strong: paste or invoke `commands/*.md` as phase prompts. | Strong: attach or reference `skills/*/*/SKILL.md` for task-specific procedures. | Strong: create specs, plans, tasks, reviews, and memory notes from `templates/*.md`. | Use `templates/memory-template.md` plus memory skills; keep durable decisions concise and never store secrets. | Use `skills/agents/*/SKILL.md` as role guides for architect, implementer, reviewer, and tester flows. | `npm run validate` | Native behavior depends on the active Claude Code workspace and attached context; avoid assuming every skill is always loaded. | Put `CLAUDE.md` at the project root, keep command prompts nearby, attach only the skills needed for the current task, and validate structural edits before final response. |
| Codex | `AGENTS.md` | Strong: paste `commands/*.md` or use them as explicit workflow instructions. | Strong: use `skills/*/*/SKILL.md` as procedures when the task calls for a focused workflow. | Strong: write normal repo files from `templates/*.md` so outputs are reviewable. | Use memory templates and memory skills as explicit files or summaries; avoid hidden context for durable project facts. | Use agent skills as role definitions or delegation checklists where the environment supports parallel agents. | `npm run validate` | Environment-specific final-response and citation rules may apply; sub-agent availability depends on the Codex runtime. | Keep `AGENTS.md` current, follow local repository instructions, use skills as scoped context, cite changed files when required, and commit only verified changes. |
| Cursor | README/manual | Moderate: copy relevant `commands/*.md` content into chat or custom prompts. | Manual: reference or paste selected `skills/*/*/SKILL.md`; no guaranteed native skill loader. | Strong: use `templates/*.md` as regular project documents. | Store durable context in project memory notes created from `templates/memory-template.md`; keep private data out of chat and files. | Manual: run role-based workflows with `skills/agents/*/SKILL.md` prompts in separate chats or review passes. | `npm run validate` | Cursor setup varies by workspace rules and chat mode; commands and skills are mostly manual unless configured by the user. | Start from the root README workflow, add concise workspace rules if useful, paste only the command or skill needed, and keep specs/plans/memory in versioned files. |

## Notes

- The validation command checks repository structure and reference metadata; use `npm run validate:references` only when changing reference-layer files.
- For all tools, prefer the smallest relevant command, skill, or template rather than loading the entire framework into every session.
